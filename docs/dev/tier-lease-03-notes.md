# TIER-LEASE-03 notes

The shared lease API. Design: `docs/design/tier-lease-2026-11-22.md` section 4 and 6.

## Routes (`backend/src/routes/tierLeases.ts`, mounted at `/api/tier-leases`, all additive)

- `GET /{key}` view (`chat` or `coding`): state, `held_by_you`, `pinned` (yours only), `releases_in_seconds` (yours only), `waiters` (count and kinds), `holder_jobs`, `decision` (the policy's hold or release reason, holder only), `pause_max_minutes`. Counts and kinds only (rule 6a).
- `POST /{key}/touch`, `/yield`, `/release`: holder only, otherwise 403 `not_holder`. Yield releases at once, or at the next boundary when a request runs (`chatLease.yieldLease`, honoured by `tick`).
- `POST /{key}/pause` and `/resume` (coding, body `session_id`): the session's owner. Pause never cuts a running turn off (state `pausing`, then `paused` when the turn ends); a paused session keeps its state in the database, so a restart loses nothing; it ends by itself after `coding.pause_max_minutes` (default 60, see TIER-LEASE-02 notes). Resume is a queued turn.
- `POST /{key}/lower`: only lowers (coding: the session's tier through `setSessionTier` and the grants; chat: releases the lease).
- `PUT /{key}/pin`: owner or admin only (`chatLease.setPin`).

## Notes

- "Holder" for pause and resume is the session's owner: a paused session holds no lease, so Resume could not require one. Someone else's session answers 404, never confirming it exists.
- OpenAPI is regenerated by the lander.
- TIER-LEASE-04 (frontend) uses these routes; TIER-LEASE-07 should register `coding.pause_max_minutes` in the spec.
- Tests: `backend/tests/tierLeasesHttp.test.ts`.

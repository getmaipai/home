A package is a folder with a `manifest.json`, an optional recipe and optional pages. Home runs it without a rebuild. The full rules live in the org standard, [PACKAGES.md](https://github.com/getmaipai/.github/blob/main/docs/PACKAGES.md). This page is the short tour.

## 🧩 Kinds

- **plugin**: tools the chat model can call, written as recipes (data, not code).
- **app**: a package whose manifest lists `contributes.pages`. It opens at `/apps/<package id>`, shows in search and favorites, and draws pages written as JSON. No React ships in a package. Bundled apps include weather, news, music, podcasts, books, shows and videos.
- **companion**, **skill**, **module** and **project** are the other kinds Home bundles; `integration`, `model`, `wakeword`, `voice`, `theme` and `reference` are also valid kinds (`spec/schemas/manifest.schema.json`).

Weather is the first app. The chat tool and the app are one package and one recipe (`backend/packages/weather`). Home bundles 63 packages in `backend/packages`.

## 📄 An app's pieces

| Piece | Where | What it does |
|---|---|---|
| Manifest | `manifest.json` | `contributes.pages[]` (one `index` is required), `contributes.data[]`, `contributes.sidebar`, `keywords` (up to 8), `min_role`, `returns_blocks` |
| Pages | `pages/<module>.json` | `page` documents using only the node types in `PACKAGE_PAGE_NODE_TYPES` (`spec/ui/app-check.ts`): `page`, `section`, `empty_state`, `progress`, `answer_blocks`, `picker`, `search`, `detail_pane`, `tabs`, `list`, `media_shelf`, `billboard`, `player`, `reader`, `split_view`, `creation_header`, `prompt_bar`, `quick_tiles`, `top_result`, `category_tiles`, `track_rows`, `result_feed` and `studio` |
| Data | `POST /api/plugins/<id>/data/<data id>` | The host resolves the place and rounds coordinates; the page never sends raw ones |
| Settings | `contributes.settings_area` | An area at `/settings/<id>` with a Settings gear in the app toolbar. Cards draw only the package's own `config[]` groups |

Home checks all of this at install time and refuses a package that breaks a rule, such as a page that binds to a data id the manifest does not declare, or an area that reuses a built-in settings id.

## ✅ Checks to carry

- The `index` page and each section validate against `spec/ui/schema.json`.
- A child, a teen and an adult each see, or do not see, the app as `min_role` says. A page may carry its own `min_role` to raise that floor (never lower it; Home refuses a package that tries). A person below a page's floor does not see the page in the app's sections and gets a 404 from its page route, and the data ids and actions only that page uses are closed to them too.
- A data call with no network shows the plain empty state.
- Fixtures use `192.0.2.x` and `example.com`.

Uninstall hides the app and keeps its state, so a favorite returns on reinstall.

## 🔗 Where the contract lives

`commons`: `spec/schemas/manifest.schema.json`, `spec/ui/schema.json` and `spec/ui/app-check.ts` (from `spec-v0.1.153` and `ui-v0.5.239`). Home's design record is `docs/plans/app-kind-2026-10-16.md`, and the weather app is traced in `docs/BACKLOG.md` under WEATHER-APP-01.

---
title: Design record
description: "Where the design notes live and how to read their status."
---

Design notes live in `docs/design` (current and recent decisions), `docs/plans` and `docs/dev.md` (history and reasoning). None of them is the authority; [Design rules](/docs/developers/reference/design-rules) is.

`docs/design/INDEX.md` lists every record with its status and the backlog row that owns it:

| Status | Meaning |
|---|---|
| current | A design still being built against, or still the reason for what exists. |
| built | All its backlog rows are ticked; kept because it explains the code. |
| partly superseded | Carries `Superseded in part` markers pointing at the rule that overrides a passage; the rest stands. |
| history | A work order, handoff, audit, bench result or research pass; the record of what happened. |

A record moves to `docs/design/retired/` only when a named record or rule replaces all of it. The backlog (`docs/BACKLOG.md`) is the source for what is built and what is missing. Whoever adds, retires or supersedes a record updates the index in the same commit.

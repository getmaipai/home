# KS-MODE-01: the search source mode

Status: built 2026-10-10. Architect verdict APPROVED (rules 0, 1, 6, 6a, 7, 11, S4, S5);
owner answers O1 and O2 and the narrow reading of `offline` apply. Full spec and tier table:
`data-scratch/design/KS-MODE-ARCHITECT-REPORT.md`.

## What it does

`backend/src/lib/retrieval/sourceMode.ts` is the one interpreter of `search.source_mode`
(`live | offline | mix`, default `mix`) and the overrides `search.source_mode.wikimedia` and
`search.source_mode.web` (`inherit | live | offline | mix`). Nothing else reads those keys.
`effectiveMode(source, band)` answers for `wikimedia`, `web` and `hosted`; `federatedLookup`
(lookup.ts), the Wikimedia gate and the page-read and image gates (packageHost.ts) and the hosted
provider (hostedSearch.ts) call it.

| Source | offline (narrow) | mix (default) | live |
|---|---|---|---|
| Library (tier K) | used | used | used |
| wikimedia-live (adult only) | never | only when the library and the web found nothing | when the web found nothing, even if the library matched |
| web, page reads, hosted (hosted adult only, needs a key) | as today; `scope: web` honoured | omitted scope: only when the library has no result; `scope: web`: yes | both, labelled |

- Minors never reach `wikimedia-live` or the hosted provider in any mode (rule 0, rule 7). Their
  web side takes the same resolved value an adult gets, so a mode can only restrict them.
- `search.source_mode.web = offline` turns off SearXNG, page reads, images and the hosted provider
  together. The result is a library answer plus a plain note (a policy refusal, not a tool failure),
  counted `mode_blocked_offline`.
- "The library has no result" means zero rows after the floor; a disambiguation row is a result.
- Counters (no text, no person id, rule 6a): `mode_blocked_offline`, `mode_mix_library_hit`,
  `mode_mix_live_fallthrough`.
- Migration (`sourceModeMigration.ts`, run once at start): a stored `search.wikipedia_fallback = false`
  becomes `search.source_mode.wikimedia = offline` unless the household already chose an override;
  true or absent changes nothing; the old row is deleted, so a second run does nothing.
- Wayback: there is no Wayback code in `backend/src` today, so there is nothing to gate yet.

## Supersedes

1. KS-02's "no household setting; the privacy row is the disclosure" wording for `wikimedia-live`.
   The household now has `search.source_mode`, and the privacy row names it.
2. The `federatedLookup` default of "both, labelled" for an omitted `scope`. Under `mix` (the
   default) an omitted scope with a library result answers from the library alone; `live` keeps the
   old behaviour.
3. The `search.wikipedia_fallback` registry key (the KS-02-PRIV stopgap declaration in
   `searchKeys.ts` is removed). Its entry leaves the spec `keys.json` in the paired commons tag.
4. The KS-02-PRIV interim ("retired, with a stored false kept"): replaced by the one-time migration
   above.

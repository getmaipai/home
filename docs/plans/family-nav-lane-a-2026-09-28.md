entirely (left nav and URL - a sibling item, FAMILY-TABS-01, handles
the URL/route half in the `home` repo) and rename the "People" nav

(`bec1ccf`, "use Tools label and route") three days ago. Read that
commit yourself first (`cd ~/Developer/github.com/getmaipai/commons &&
git show bec1ccf`) - it is the exact shape of the commit you're about
to make, just a different edit.

   `ui/src/dashboard/layouts/full/vertical/sidebar/sidebaritems.ts`.
   The array is `SidebarContent: MenuItem[]` (lines 56-100 as of this
   writing; re-read the file, don't trust the line numbers if the file
   has moved). Two edits:
   - Delete the whole "Tools" item object (the one with `name: "Tools"`,
     `url: "/next/tools"`, and its header comment about "internal

     item's `name: "People"` to `name: "Family"`. Leave its `url:
     "/next/people"` and `icon: Users` unchanged - FAMILY-TABS-01
     keeps the route path as-is, only the label changes here.

     ... Labels and routes only - the template's own nav-items/Sidebar
     components render this unmodified") stays accurate as-is; don't
     rewrite it, just leave it truthful (it will be, after your edit).
2. Bump `ui/package.json`'s `"version"` field by one patch version from
   whatever it currently reads (mirror `bec1ccf`'s exact pattern - that
   commit bumped `0.5.61` to `0.5.62` alongside its own sidebaritems.ts
   edit). Note the current `ui/package.json` version already trails the
   latest tag number (drift that predates this item) - just bump
   from whatever `ui/package.json` says today; don't try to reconcile
   it with the tag sequence, that's out of scope.
3. Pick the next tag: `git -C ~/Developer/github.com/getmaipai/commons
   tag -l "ui-v*" | sort -V | tail -1` to confirm the latest, then use
   the next patch number after that (as of this writing the latest is
   `ui-v0.5.78`, so the next would be `ui-v0.5.79` - re-check, don't
   assume this is still current when you run it).
4. Commit in `commons`, staging only the two files you edited (`git
   add ui/src/dashboard/layouts/full/vertical/sidebar/sidebaritems.ts
   ui/package.json` by name, never `-A`). Commit message: `ui-vX.Y.Z:
   drop Tools, rename People to Family` (matching the `ui-vX.Y.Z: <what>`
   convention `bec1ccf` and its neighbors use). Add one line to
   `commons/docs/BACKLOG.md` or `docs/dev.md` (whichever that repo's
   existing entries for a sidebar/nav change use - check a recent one
   first) noting the sidebar edit and the new tag, staged and committed
   in the same commit. Run `commons`'s own `bash scripts/check.sh` first
   and confirm it's green before committing (it's a small workspace;
   this should be fast - if it's not, or if it hits the machine-wide
   gate lock, that's expected and fine, just wait your turn, don't
   bypass it). Then `git tag ui-vX.Y.Z` on that commit. Push both the
   commit and the tag: `git push && git push origin ui-vX.Y.Z`.
5. Back in your `home-codex` worktree: edit `scripts/check.sh`'s
   `UI_TAG="ui-v0.5.78"` line to the new tag, and
   `frontend/package.json`'s `"@maipai/ui": "file:../../commons-tags/
   ui-ui-v0.5.78/ui"` line to the new tag's path (same substitution,
   both must name the identical tag). Run `bash scripts/check.sh` -
   this is what actually creates `../commons-tags/ui-ui-vX.Y.Z/` as a
   fresh detached worktree of the tag you just pushed and resolves the
   pin against it. If it fails because the tag isn't visible yet, `git
   -C ~/Developer/github.com/getmaipai/commons fetch --tags` and retry
   once. Then, in `home-codex/frontend/`, run `bun install --force`
   (not a plain `bun install` - the pinning note in `home/AGENTS.md`

6. Tick `FAMILY-NAV-01` in `home/docs/BACKLOG.md` (add a new item under

   home pin-bump commit) and the one-line summary of what changed.
   Stage `scripts/check.sh`, `frontend/package.json`,
   `frontend/bun.lock`, and `docs/BACKLOG.md` by name; commit.

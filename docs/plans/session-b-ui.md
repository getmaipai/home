# Session B: the UI, on frameworks (frontend and the UI schema)

A self-contained work order for one coding session. Point a session at
this file and it codes until every step is done and merged. Session A
(`session-a-intelligence.md`) runs at the same time on the backend and
the record spec; the two never edit the same files, and the API Session
A adds is frozen in its "Contract with Session B" section, which you
build against. Written 2026-09-05 from the audit recorded in
`docs/BACKLOG.md` ("The 2026-09-05 audit", "UI / shell") and
`docs/dev.md`.

Jesse's standing instruction for this session (2026-09-05): **hand-carved
React is not acceptable; use frameworks.** The kit today hand-styles
Radix to shadcn's API, every page is bespoke React, the chat thread is a
`whitespace-pre-wrap` bubble, and there is no data layer, no lint, no
service worker and no schema renderer. Org principle 6 (prebuilt over
hand-built) and platform plan 6.3 ("`@maipai/ui` is a thin layer over
shadcn/ui on Radix and Tailwind v4... it never reimplements a widget the
library ships") say the same thing. This session makes the frontend
match that sentence.

## The goal

At the end of this session the frontend is assembled from maintained
parts, every page is data, and the family can find and reach anything
from one box. Concretely:

- The kit is shadcn/ui components generated by its CLI over Tailwind v4,
  with one icon set, one token file, and a lint that keeps it that way.
- The shell is the library's sidebar with a data-driven nav, a
  five-entry bottom bar on phones, a focusable rail on TV, a profile
  switcher, and a command palette on every surface.
- Home is a real home: a greeting with who is here, a strip of pinned
  apps the family chose, and one prompt box that is both search and
  chat.
- Chat runs on a maintained assistant UI framework over the existing
  turn stream: streaming markdown, stop, copy, regenerate, a thread
  list, a memory-updated chip.
- People, Memory, Privacy and Settings render from JSON page
  definitions in `spec/ui/pages/` through one renderer; a change to a
  primitive reaches every page, and Go can read the same files later.
- A screenshot matrix covers every page at every surface in both themes,
  with accessibility checks, in the pipeline.

## Rules for this session

- **Worktree, because Session A is editing the same repo.** Create one
  with `EnterWorktree` (or `git worktree add ../home-b main`), work
  there, and merge to `main` and delete it before the session ends.
- **Own data directory and ports.** Backend for your manual checks:
  `MAIPAI_DATA_DIR=<worktree>/data-b PORT=8798 bun run dev` in
  `backend/`; Vite proxies to `localhost:8787` by default, so run it
  with the proxy target overridden to 8798 (an env var read in
  `vite.config.ts` is fine; keep the default). Never touch the shared
  `data/`.
- **Rebase often.** `git fetch && git rebase origin/main` before each
  commit. Session A's commits touch `backend/`, `spec/schemas`,
  `spec/gen`, `spec/fixtures`, `spec/records`, `spec/safety`,
  `spec/llm`, `spec/tests` and its own `docs/dev.md` sections;
  conflicts should be none.
- **`docs/dev.md` is append-only for you.** One section per shipped step
  under a heading that starts with `## Session B:`. `docs/BACKLOG.md`:
  check off only what you ship, add gaps you find under the right
  section.
- **Frameworks, not hand-rolled.** Before writing a component, hook or
  utility, check whether the library already ships it. A missing
  primitive is a gap to flag in dev.md, not a reason to hand-build.
  Every dependency: AGPL-compatible licence (MIT, Apache-2.0, BSD),
  pinned in `package.json`, listed in `NOTICE` if it requires
  attribution, installed with `bun add`, never vendored.
- **Tests in the repo's shape.** `bun:test` with happy-dom and Testing
  Library (`frontend/tests/preload.ts`); read a nearby test before
  writing one. Every bug found live becomes a regression test first.
- **Definition of done per step:** `scripts/check.sh` green (you add
  the lint to it in step 1; it must stay green), the change seen in the
  running app at phone and desktop widths, the `code-review` skill at
  medium effort on the diff, docs in the same commit, one commit per
  step, never `git add -A`.
- **Screenshots are looked at.** Any screenshot you take is opened and
  checked before it is used or shown.
- **Writing:** no em dashes, no AI filler, dad-test copy in the UI. The
  prose lint in `check.sh` will catch the first two.

## Framework decisions (verified 2026-09-05 against npm, GitHub and the official docs; re-check the version column at install and pin what you install)

| Need | Use | Verified today | Why, and the gotcha |
|---|---|---|---|
| Components | shadcn/ui via its CLI: `shadcn init -t vite -b radix` | `shadcn` 4.21.0, MIT | The mandated kit base. Pass `-t vite -b radix` explicitly (the default preset is Next). Tailwind v4 theming is CSS variables in `:root`/`.dark` mapped through `@theme inline`; `tw-animate-css` replaces `tailwindcss-animate`; components carry `data-slot`, no `forwardRef`. `Toast` is deprecated: use Sonner. |
| Icons | `lucide-react` through `kit/icons.ts` only | present | Already the rule; lint enforces it |
| App shell | shadcn `Sidebar` (`collapsible="icon"`, `SidebarProvider`, `SidebarRail`, mobile via Sheet at 768 px through `useIsMobile`) plus a bottom tab bar on phone from shadcn buttons | in the registry | `useIsMobile` is viewport-only; the `far` surface needs `useSurface()` (below), not this hook |
| Command palette and search | shadcn `Command` (cmdk) | in the registry | The unified search box and Cmd/Ctrl+K palette |
| Chat | `@assistant-ui/react` with `useLocalRuntime` and one `ChatModelAdapter` (`async *run({ messages, abortSignal })`) over `POST /api/turn/stream`; `useExternalStoreRuntime` if you end up owning message state | 0.15.18, MIT, peer React 18 or 19 | The adapter yields **cumulative** content, not deltas: accumulate the NDJSON `delta`s and yield the running text. Branching, edit, reload, cancel come free. Install into the project with `shadcn add @assistant-ui/thread @assistant-ui/thread-list`. Docs are Next-first; skip the `ai` SDK step. Persistent thread lists need a `RemoteThreadListAdapter` (yours, over the conversations API). Wrap in `TooltipProvider` yourself (issue 3933). |
| Markdown | `@assistant-ui/react-markdown` (react-markdown 10, remark-gfm 4, rehype-sanitize 6) | shipped with assistant-ui | `streamdown` 2.6.0 (Apache-2.0) is the streaming-safe alternative but replaces assistant-ui's markdown rather than adding to it and needs a Tailwind `@source` line; use it only if unterminated code blocks mid-stream prove ugly |
| Data layer | `@tanstack/react-query` | 5.102.8, MIT | Caching, retries, loading and error state once, not per page |
| Forms | shadcn `Field`, `FieldLabel`, `FieldError` with react-hook-form `Controller` and the Zod resolver | current forms guide | The older `form` registry item still exists but is legacy; use `Field` |
| Router | `react-router` | v8.3.1 current; v7.18.3 still patched | Decide in step 0: v8 is ESM-only, needs React 19.2.7 or later and Vite 7 or later (all true here), and drops `react-router-dom` (DOM exports move to `react-router/dom`). Prefer v8 since the imports are being touched anyway; record the choice. |
| Schema pages | json-render: `@json-render/core` and `@json-render/react`, with `@json-render/shadcn` as the reference catalog | 0.20.0, Apache-2.0, peer Zod 4 and React 19.2.3 or later | Spec is `{ root, elements, state }`, a flat `elements` map keyed by id with `type`, `props`, `children`, `slots`, `visible`; bindings `$state`, `$bindState`, `$cond`, `$template`, `$computed` on JSON Pointer paths; actions declared in `defineCatalog(schema, { components, actions })`. Hand-authored JSON files are explicitly supported. It is 0.x and moving fast: pin exactly. No SwiftUI renderer. |
| Go's renderer, recorded not built | A2UI (`@a2ui/react` 0.11.0, Apache-2.0) evaluated and written up | verified | Official renderers: React, Angular, Flutter, Lit, markdown; SwiftUI/tvOS only as a 55-star community port. It is a streaming update protocol, not a page document, and its React package pins Zod 3, which conflicts with json-render's Zod 4. Record why json-render won for the web and what a SwiftUI renderer of our page JSON would need. |
| TV focus | `@noriginmedia/norigin-spatial-navigation` | 3.3.0 (core 4.1.1), MIT, peer React 16.8 or later | `useFocusable`, `FocusContext`, `setKeyMap`, `pause()`/`resume()`. Radix overlays (Dialog, Sheet, DropdownMenu) trap DOM focus and handle arrow keys themselves; `pause()` Norigin while any overlay is open and `resume()` on close, or make the overlay's items Norigin focusables with `isFocusBoundary`. The Bam and lrud alternatives are dormant. |
| Input mode | `usehooks-ts` `useMediaQuery` plus a small event listener, together as `useSurface()` | 3.1.1, MIT | Nothing on npm detects a TV remote; on webOS and Tizen it arrives as arrow `keydown`, gamepads via `gamepadconnected`, touch as `(pointer: coarse) and (hover: none)`, pointer via `pointermove`. Media queries report capability, events report what is in use; the hook needs both. About thirty lines, the one piece of hand-written detection. |
| PWA | `vite-plugin-pwa` | 1.3.0, MIT, Vite 8 peer, Workbox 7.4 | `onNeedReload` client callback for the reload-once rule |
| Error boundary | `react-error-boundary` | MIT | Stale-chunk recovery and a real error state |
| Lint | ESLint 9 flat config, `typescript-eslint`, `eslint-plugin-react-hooks`, `eslint-plugin-jsx-a11y`, `eslint-plugin-better-tailwindcss` with `entryPoint: "src/index.css"`, core `no-restricted-imports` for icons, `no-restricted-syntax` for hex in `style={{}}` | better-tailwindcss 4.7.0, MIT, peer Tailwind 4.1.17 or later | Rules `no-unknown-classes`, `no-conflicting-classes`, `no-restricted-classes` with the documented arbitrary-value pattern to ban `bg-[#fff]`-style literals |
| Screenshots and a11y | Playwright (present) plus `@axe-core/playwright` | MIT | The matrix UI.md describes |

If a row turns out wrong at install time (a breaking release since

### Step 1: the kit on shadcn, and the lint (M)

- `shadcn init` for Vite and Tailwind v4 in `frontend/`; map the
  existing `kit/tokens.css` palette onto shadcn's CSS variables so the
  look does not change, one token file, light and dark.
- `shadcn add` for: button, input, textarea, select, switch, checkbox,
  avatar, card, badge, skeleton, tabs, dialog, alert-dialog, sheet,
  tooltip, dropdown-menu, command, sidebar, form, sonner (toast),
  scroll-area, separator, progress. Generated components live in
  `frontend/src/kit/ui/`; the old `kit/components/*` are deleted and
  every import repointed. `kit/primitives/*` stay as the layout and
  pattern layer but are rebuilt on the generated components (Toast
  becomes Sonner; Form becomes shadcn Form; Progress uses the library's
  progress and skeleton; List, CardGrid, MediaShelf, DetailPane,
  SplitView keep their props and lose any hand-written widget inside).
- Add the two primitives the audit found missing from the pattern
  layer: `AsyncState` (loading skeleton, error with retry from the
  catalogue message, empty state) and a batch-selection bar (the
  Carbon-style bar UI.md names; lift it from `PeoplePage.tsx`).
- ESLint flat config in `frontend/`: the plugins above; rules that fail
  on `lucide-react` imports outside `kit/icons.ts`, on hex or rgb
  literals in `src/apps` and `src/shell`, on raw `<button>`/`<input>`
  in `src/apps`, and on `hover:` variants without a focus equivalent.
  `bun run lint` runs it; `scripts/check.sh` calls it.

Tests: every primitive keeps its existing tests green; new tests for
`AsyncState` and the batch bar; a lint fixture proving each rule fires.
Acceptance: every existing page renders unchanged at phone and desktop
(screenshot before and after, looked at).

### Step 2: the shell (M)

- Nav from data: a `nav_entry` node in `spec/ui/schema.json` and a
  registry the shell reads (core pages register theirs; a package's
  manifest `contributes.pages` will feed it later, note the hook). The
  hardcoded list in `Shell.tsx` goes.
- Desktop and tablet: shadcn `Sidebar` with labels, collapsible to
  icons by the person's choice (never the default), the fixed rows
  Search, Home, then "Your apps" (pinned, reorderable later), then
  More. Auto-collapse when a consumption mode says so (a shell flag,
  unused until a media package exists).
- Phone: a five-entry bottom bar (Home, Chat, Search, and the first two
  pinned) with More opening a sheet; safe-area insets; the keyboard
  offset via `visualViewport`.
- TV: the sidebar as a focusable rail through the spatial-navigation
  hook; no hover anywhere; the tvOS type scale applied by a `far`
  surface class.
- `useSurface()` in the kit: `{ pointer: "fine"|"coarse", hover,
  input: "touch"|"pointer"|"keyboard"|"remote", far: boolean }` from
  media queries plus a keydown/gamepad listener. Every responsive
  decision reads it; no component reads `window` directly.
- Header: wordmark, the bell, and a profile switcher (avatar opens the
  sign-in picker; PIN prompt for secured profiles) replacing sign-out
  as the primary action, with sign-out inside the menu.
- Appearance setting: `backend/src/settings/uiKeys.ts` declares
  `ui.appearance` (`system|light|dark`, person scope) and
  `ui.pinned_apps` (a list, person scope); the shell honours the first
  and drives `theme-color` from it; `prefers-reduced-motion` disables
  transitions and spinners' spin.

Tests: nav renders from the registry; bottom bar under 640; rail on
`far`; `useSurface` transitions; profile switcher opens the picker;
theme setting applies. Acceptance: phone, desktop and a 1920-wide
`far` emulation screenshot of Chat and Home, looked at.

### Step 3: the data layer (S)

TanStack Query for every fetch in `lib/api.ts` consumers: one
`QueryClient`, query keys per resource, mutations with invalidation,
`AsyncState` bound to query status. The copy-pasted load/error/retry
triads in Chat, Memory, Privacy, People and the settings renderer are
deleted. The notification bell moves from its own 15 s poll to a query
with `refetchInterval`.

Tests: one page test per migrated page proving loading, error with
retry, and data render through the shared state.

### Step 4: chat on assistant-ui (M)

- Runtime: `useLocalRuntime` with one `ChatModelAdapter` whose
  `run()` reads `POST /api/turn/stream`, accumulates `delta`s and
  yields the cumulative text (the framework expects running content,
  not deltas), maps `turn_meta`, `spoken_cue`, `done` and `error`, and
  honours `abortSignal` for stop. The
  sentence-chunked TTS and the thinking-cue playback keep working (they
  hook the same deltas). "Think longer" is a composer toggle from the
  kit, not a raw button.
- Thread: streaming markdown with code blocks and copy; per-message
  copy, regenerate, "remember this" (`POST /api/memory` with the turn
  id as `source`) and "forget this" (archive) actions; timestamps and
  day dividers; `aria-live` on the streaming message; the crisis banner
  and failed-send state preserved.
- Composer: multi-line textarea, Enter to send, Shift-Enter newline,
  suggested prompts on the empty state (three, from the installed
  packages' routing examples).
- Threads: a `RemoteThreadListAdapter` over `GET /api/conversations`
  (the local runtime alone does not persist threads) with new, rename,
  delete, batch delete and clear-all through the batch bar; the current
  thread id passed as `conversation_id`. Until Session A's routes land
  on `main`, build against a local mock that returns one thread, and
  swap to the real routes when they merge (rebase and check).
- Memory-updated chip: when a `memory.updated` notification arrives for
  the current thread, show the chip on that message, linking to the
  Memory page filtered by those ids.

Tests: the adapter maps a scripted NDJSON stream to messages, stop
aborts, error surfaces; message actions call the right routes; thread
CRUD; the chip appears on the notification. Acceptance: a real
conversation against the running backend with the stub model, phone
and desktop, screenshots looked at.

### Step 5: schema pages (M-L)

- Catalog: a Zod-typed json-render catalog whose components are exactly
  the kit primitives and pattern components (Page, Section, List,
  CardGrid, MediaShelf, DetailPane, SplitView, Form, EmptyState,
  Progress, AsyncState, MessageThread as the assistant-ui thread), with
  data bindings to routes and actions `navigate`, `call`, `confirm`,
  `ask`, `play`.
- `spec/ui/schema.json` gains nodes for the five primitives and
  `nav_entry`, and a test that the catalog and the schema agree (each
  React primitive's props are a superset of its node; every node kind
  has a catalog entry). Whether the schema is generated from the
  catalog or the catalog validated against the schema is your call;
  record it. Fix the README lines that say the turn engine is
  single-shot.
- Pages: `spec/ui/pages/{people,memory,privacy,settings}.json` authored
  against the schema; the React pages become thin mounts of the
  renderer. People keeps its batch behaviour through the batch bar
  node; Memory gains multi-select archive and clear-all (the backlog's
  named consumer) on `List`. Chat stays a schema page whose
  `message_thread` node renders the assistant-ui thread from step 4.
- Record A2UI's current renderer list and spec shape in dev.md as the
  path for Go's SwiftUI renderer, with what would have to change.

Tests: each page JSON validates; each page renders from JSON in a
component test with mocked queries; the catalog/schema agreement test.
Acceptance: all four pages in the running app, phone and desktop,
unchanged behaviour, screenshots looked at.

### Step 6: home and unified search (M)

- Home (`/`) is shell-owned and schema-defined: a greeting with the
  signed-in person's name and time of day, "who is here" from the
  active sessions the backend already knows (household-level only until
  presence exists), a "today" section with the two cards that can be
  real now (a weather card calling the weather plugin through the
  existing turn route with a fixed utterance, cached by the query
  layer; a "recent memories" card from `GET /api/memory?since=`), a
  pinned-apps strip driven by `ui.pinned_apps` with pin and unpin in
  each app's header, and the prompt box.
- The prompt box and the palette are one component on shadcn
  `Command`: providers for pages and apps (from the nav registry),
  people, memories, conversations, settings keys (label and help text),
  commands, each independent and best-effort (a failing provider
  contributes nothing), six results per provider, grouped, last token
  prefix-matched; the final row is always "Ask MaiPai: <text>" which
  opens Chat with the text sent. Cmd/Ctrl+K everywhere, the Search nav
  row on every surface, and on `far` the palette is a page with no
  free text entry beyond the remote's keyboard.
- Chat moves to `/chat`; `/` is Home; old links keep working through a
  redirect.

Tests: greeting by time of day; pin and unpin persist through the
setting; each provider returns grouped hits from mocked queries; a
throwing provider does not break the search; "Ask MaiPai" navigates
with the text. Acceptance: Home and the palette at phone, desktop and
`far`, screenshots looked at.

### Step 7: settings as an editor (M)

Per the backlog's Settings item and SETTINGS.md: a schema page with a
tree sidebar (sections and subsections from the registry's `lives_in`
paths), a search filter over label and help text, scope tabs (household,
me, this device) with URL-bound active tab, each setting stacked title,
description, control. `SettingField` gains `duration`, `time`, `person`,
`media` and a write-only secret flow so the custom sections (PIN, HF
token, commands, backups, voice catalog, cloned voices, models, routing
stats) can be declared where their keys allow; sections that are real
management surfaces rather than settings (models, backups, voices,
commands) become their own schema pages linked from the tree. No global
"advanced" toggle (recorded decision).

Tests: tree from registry; search filters; tabs bound to URL; each new
selector round-trips; a secret field never displays its value.
Acceptance: every existing setting still editable in the running app.

### Step 8: PWA, resilience, motion (S-M)

`vite-plugin-pwa` with maskable 192 and 512 icons, navigations
network-first with an offline page, assets cache-first, full passthrough
on Firefox (local network access), reload exactly once on
`controllerchange` (legacy's rules, each learned from a real failure:
a cached index once pinned old asset hashes for several reloads).
`react-error-boundary` at the shell and page levels with a stale-chunk
retry once per session. A boot watchdog capped at three reloads. Type
floor: nothing under 16 px on phone (the bell badge and thread labels
are below it today).

Tests: the boundary catches and offers retry; the watchdog stops at
three; type-floor lint or test. Acceptance: install to the home screen
on a phone-width emulation, go offline, see the offline page.

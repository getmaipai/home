# IMGQ-09: show pictures when asked

Date: 2026-10-12. Verdict: `data-scratch/architect/IMGQ-09.verdict` (a APPROVED, b APPROVED with constraints, c NEEDS-RULE-CHANGE, not built).

## Supersedes

IMGQ-07 B's wording of the `show_images` description and `subject` argument. The IMGQ-07 B text stays inside the new one; the
examples block and the shorter description replace its trigger sentences. IMG-QUALITY-01a's ban on describing unseen looks is kept.

## What was built

(a) Wording. Top-level description (189 characters) and four worked calls in the `subject` argument ("who is Frida Kahlo", "what is the
Space Needle", "what does a pangolin look like", "I love my old Toyota Supra"), plus four requests that never call it. It lives in the
manifest, which is read only on the adult offer path (`answerImagesAllowed`), so teens, children, spoken, temporary and bare turns never see it.
No counts, no description of how anything looks.

(b) Re-ask (`reAskForShowImages`, `turnNext.ts`). When the turn offered `show_images`, the first pass ended in text with no tool call
at all, and the reply was kept, the model is asked once more after the reply has streamed, `tool_choice: "auto"` only, thinking off,
200 tokens, the stream gate cut off so none of its text shows. A `show_images` call starts the normal picture pipeline and the gallery
is placed after the reply. Any failure is no gallery. Built and measured, but **off by default**: on with `MAIPAI_IMGQ09_REASK=1`, pending Jesse's call on its false offers. Gated by the same `answerImagesAllowed`.

(c) not built. A shadow-only logged number was not added.

## Measurement

Bench `backend/scripts/bench/answer-images.ts`, ON arm, remote Stack, 3 repeats, tuned on dev only (a1 0.67/0.07, a2 0.92/0.37 over-triggered,
a3 0.64/0.13 recall/false offers), then held-out once. Paired bootstrap 95% over rows (`answer-images-compare.ts`). Held-out (9 V, 8 N rows):

| Arm | Recall | False offers |
|---|---|---|
| plain (IMGQ-07 base) | 0.28 | 0.06 |
| reworded (IMGQ-07 B) | 0.54 | 0.25 |
| (a) wording alone | 0.50 | 0.03 |
| (a)+(b), first run (tool description 189 characters) | 0.92 | 0.22 |
| (a)+(b), final wording (FAST-03 forced the tool description under 120 characters; the trigger sentences moved to the argument text) | 0.78 | 0.33 |

(a) vs plain: recall +0.22 [0.00, 0.44]; vs reworded: -0.04 [-0.32, 0.26], false offers -0.22 [-0.43, -0.03]. Bar 0.80 missed, so (b) was built.
(a)+(b) vs plain: recall +0.64 [0.58, 0.67], false offers +0.17 [0.06, 0.31]; vs (a): recall +0.42 [0.22, 0.61], false offers +0.19 [0.03, 0.36].
The first run met the bar; the final-wording run (the one shipped) narrowly missed it: recall vs plain +0.50 [0.31, 0.67], vs reworded +0.24 [0.01, 0.47]; false offers vs plain +0.28 [0.14, 0.44], vs reworded +0.08 [-0.11, 0.29]. The two runs differ by more than their intervals suggest, so treat 0.78 to 0.92 as the range. False offers (0.22 to 0.33) match or exceed the already shipped reworded arm (0.25) and are far above (a) alone (0.03); offered non-entity questions
were capital of Japan, serendipity, photosynthesis, speed of light, virus vs bacterium, DNS. Latency: median total turn 8.5 s to 11.8 s
(the re-ask adds about 3.4 s after the answer is on screen); median first word unchanged at 1.9 s.

After the review, the re-ask offers only show_images and stops after 8 s; the benches above ran with the full tool list and no cap, so this exact shape is not re-measured (the feature is off by default).

Prompt cost: the argument text adds about 250 tokens to every adult written turn (spokenSearch.test.ts window 4096 to 4608).

Private-person tile check on new offers: the new offers go through the unchanged IMGQ-07/08 tile pipeline; not re-judged here (see IMGQ-11/13).

## Reuse check

- **H3 runtime, one or two?** The Stack's H3 video family (H3-VIDEO-STACK-01, landed) runs the `yshenaw` MLX port's command line (`generate_staged.py`): measured, it implements text and first/last-frame (FL2VA) only, with no Ref2VA reference conditioning, no LoRA stack and no aligned guide, and its quantized layout is built from the Comfy-Org FL2VA files. mere.run (MIT, Swift) already loads the Ref2VA MLX 8-bit pack and implements `--reference image/video/audio` and `--h3-frame`; our patch adds the stackable LoRA and the aligned guide. So Swap cannot run on the port without re-implementing Ref2VA in Python, and the Ref2VA pack is mere.run's format. Rule of one implementation (platform principle 1): this note therefore also opens **H3-ONE-RUNTIME-01** (bench, after Swap): run H3 text and first/last-frame clips through mere.run too (it supports `--h3-frame`), compare speed, memory and look with the port, and retire the port if mere.run matches. Until that bench, two runtimes serve one model family and the Stack hides it behind one video family and one status entry.
- Existing code reused: `startVideoEditJob`, the edit run and gate functions (`editGate.ts`), `resolveCast`, the Stack heavy gate and `videoJobs`, `stackEdit.ts` (`audio_overlay`, `mute`, `trim`), the Library creation store, the licence flow `lib/licenceFlow.ts` (LICENCE-ACK-01).

## 2. The engine (replaces "LTX IC-LoRA plus SAM 2.1" for Swap; LTX stays the fallback while H3 is not installed)

- **What works, measured (2026-11-16):** MiniMax H3 Ref2VA (8-bit) with the community Head Swap LoRA, the real clip as an aligned guide, one to three photos of the replacement person as reference pictures. 56 frames (2.3 s) a segment at 640x480 (peak about 112 GB; 512x384 about 85 GB); a continuous 124-frame run copies the guide instead of swapping, so longer clips are chained segments, then the **original audio** is laid back and a light upscale (lanczos plus unsharp 0.4, no AI restore, so an old clip keeps its look). Real clips judged by the owner: the head and the 90s look are right; the mouth follows the source (small at 640 px) and the voice stays the original's.
- **One new Stack component, owned by the Stack (rule 11):** `h3-swap` engine = a pinned fork of the MIT mere.run Swift runtime with our patch (stackable `--h3-lora`, aligned `--h3-guide-video`), the Ref2VA 8-bit pack, the Head Swap LoRA (pins, sizes, hashes), installed from Settings, AI and models like every other engine (a card with its true size, licence and readiness, in the setup wizard list too; the H3 licence id is given to the household licence acknowledgement, LICENCE-ACK-01, `lib/licenceFlow.ts`: an uncovered licence asks once, no per-engine accept). Nothing is vendored in Home; the patch lives in a pinned fork the Stack builds and tests. No ComfyUI (rule 11 and the owner's earlier ruling stand: the community LoRAs are used, their ComfyUI workflows are not).
- **Stack route:** `POST /v1/videos/swap` (source clip, one to three reference pictures, a one-line description of the person, size, window), an ordinary Stack job: heavy-gate lease and admission with measured peaks, progress by segment, cancel kills the process tree, `GET /stack/v1/video` `qualities.h3_swap` says ready, limits and peak. It runs one at a time and never beside another heavy job (the memory watchdog trips otherwise; measured).
- **Memory and tiers:** Max only, adults only (the Max lease and the 110 GB GPU limit are an admin setting: Settings states it plainly and the Stack checks it; the Stack reports "not ready: needs more GPU memory" instead of crashing). Reduced, Standard and Boost never offer it.

## 7. Dependency resilience (owner ask, 2026-11-16: "what if the person takes it off GitHub, Civitai or Hugging Face")

Today's rule ([RELEASES-AND-DEPENDENCIES.md](../../../.github/docs/RELEASES-AND-DEPENDENCIES.md), "Third-party code: models, binaries and datasets are fetched": pinned version, pinned URL, checksum verified, a clear failure when offline) catches a changed file but not a **removed** one: new installs would fail and we could not recover the exact file. The Swap work depends on several single-author pieces (the patched mere.run, the Head Swap and Character Swap LoRAs, the community-converted Ref2VA pack). The rule that follows, to be applied to every community dependency (this feature first):

1. **Code: prefer GitHub projects with a permissive licence, and never rely on the upstream staying up.** We do **not** create fork repos (the licensing doc says every repo we host carries our AGPL licence and copyright, and a fork keeps the upstream's). Instead: the Stack pins the upstream **commit** and checks the source's sha256; the exact source tarball is kept in a **private archive**; our patch is a **diff file in our own repo** (our work, our licence, with the upstream credit in NOTICE); and the **patched build is published as an org release asset** that the Stack downloads (the pattern MODE-ENGINE-01 already uses). If upstream vanishes, the archive plus our diff rebuild the same binary. A project with no licence is not used without the author's permission.
2. **Weights: pin the source, the revision and the sha256; keep a private archive copy** of every file we depend on, outside any public location, for our own backup. A **public mirror only for files whose licence clearly allows redistribution** (Apache-2.0, MIT, CC-BY), with the licence and credit kept. Files under the MiniMax H3 licence, a no-redistribution or non-commercial licence, or Civitai terms that forbid re-hosting are **never publicly mirrored**: the install gets a "bring your own file" path (a clear message naming the original source, the hash and where to put the file) if the original disappears.
3. **Single-source features are optional and off by default**, with an official fallback installed (LTX for video), as section 5 already says for H3.
4. **Respect authors:** credit and link back; remove a mirror on a request; never scrape against a site's terms.
5. This is an engineering and licence question, not legal advice: where H3 would enter a US release, a lawyer or MiniMax decides first (section 5).

# B-kit: commons kit and token audit for PRO-LOOK-01 (read-only, 2026-11-08)

Source read: commons `origin/main` (ui 0.5.533, extracted to scratch; the local commons checkout is 19 commits behind), the note
`docs/design/PRO-LOOK-01.md` sections 5, 7, 16-24, and Home's pin (`ui-v0.5.464`). Paths are under
`<org>/commons/ui/src/` (written `src/` below). Nothing was modified.

## 0. Findings that change the plan (read first)

1. **Home is 69 tags behind.** Home pins `ui-v0.5.464`; commons is at `ui-v0.5.533`. The pinned `PhoneNav` has only `variant: "bar" | "floating"` (no `docked`,
   `label`, `trailing`, `more`). A pin bump (`bash scripts/pin.sh commons ui-v0.5.533`, lands itself) is slice 0; every gallery judgement before it is against old code.
2. **The `--font-size-*` tokens barely drive anything.** Outside `tokens.css` only `primitives/Wizard.tsx` reads `--font-size-body/title`. The kit sets text with
   Tailwind `text-sm/base/lg` (about 870 uses). Re-valuing `--font-size-body` from 13.5 to 15/17 therefore changes almost no screen; the note's "every screen
   changes at once with no layout move" is false for type. The real lever is Tailwind v4's `--text-*` theme variables (`globals.css` already defines `--text-40`)
   plus new semantic utilities, so `text-sm` etc. map to the note's scale, and the ease root `font-size` still scales rem text.
3. **Looks are not in `tokens.css`.** The 8 Looks are 16 blocks (`.style-<look>` and `.dark .style-<look>`) in `src/dashboard/css/globals.css` (neutral, stone, zinc, mauve,
   olive, mist, taupe, navy; navy has both, lines 189-710). They set only shadcn roles (`--background --card --popover --muted --secondary --accent --border --primary
   --foreground --sidebar* --chart-*`). `--surface-page/-card/-pane/-sidebar/-stage` in `tokens.css` are **navy hex literals, not Look-driven** (also re-mapped by
   `[data-surface="studio"]`). So the note's `surface-0..2` must be derived with `color-mix` from `--background`, `--card`, `--muted` (Look-driven), never from `--surface-*`.
   Done that way, 8 Looks x light/dark come for free and need one resolution test, not 16 hand-set values.
4. **`--art-*` currently does the opposite of section 24 item 2.** `tokens.css` lines 2299-2307: `--art-foreground: var(--foreground)`, `--art-scrim` and `--art-overlay` are
   `--background` mixes, so in a light Look the scrim is light and text is dark. `contrast.test.ts` (around line 334) encodes that. Making it "fixed light text on fixed dark
   scrim" is a value change of an existing token, visible today in Player, Billboard, `MediaTileOverlay`, VideoPlayer badges (not additive). Needs an explicit decision (see 4.3).
5. **No "kit gallery" page exists.** Parts have `*Showcase.tsx` files in commons (about 25, e.g. `elements/VideoPlayerShowcase.tsx`, `ui/TabsBottomShowcase.tsx`,
   `settings/SettingsShellShowcase.tsx`) but only the two settings showcases are mounted (Home `frontend/src/shell/pages/UiShowcasePage.tsx`, `/dev/ui`, admin only). Captures are
   Home scripts: `scripts/screenshotShowcase.ts` (viewports 1440x900 and 390x844 only; light and dark only for `--calm` chat captures) and `scripts/screenshot.ts` (full matrix, `--look-review`).
   "Rendered by hand to check 1440 and 390 in both themes" (comment in `VideoPlayerShowcase.tsx`) is the current practice. The section 19 gallery (every part, 390/1440, light/dark,
   child, 4 Look/scheme pairs) is **new work**: see slice G in section 7.
6. **Kit targets are 48, the note says 44.** `ui/button.tsx` sizes: default `h-12`, `icon` `size-12`; `--target-min: 48px` (ease generator; large = 76). Note section 5.1 says "44 pt hit area stays" and
   round buttons 44. Tests `touch-target-floor.test.tsx`, `hitArea.test.tsx` enforce 48. Resolve: keep 48 hit area with a 44 visible control (the kit's `hitArea()` pattern), or Jesse changes the floor.
7. **Studio scope conflicts with one look.** `[data-surface="studio"]` (tokens.css 2480-2565) forces near-black plus lime `--primary` whatever the Look. Section 9a/18 wants studios on the shared
   tokens with `accent-create` yellow and a cream primary. That block (and `studio-surface.test.tsx`, `surface-stage.test.ts`) must be reworked or retired in the studios slice, not the kit-1 slice.
8. **Generator trap.** `scripts/gen-ease-tokens.ts` regex-reads `--font-size-(title|section|metric|body|supporting): Npx` from the whole file and writes `html[data-ease-text="N"]` blocks (specificity 0,1,1)
   that beat any `:root` or `@media` value. A phone/desktop split of `--font-size-body` (17 vs 15) written as a media query would be silently overridden by the ease block at step 100. The generator must emit the
   media variants and learn the new names (row, badge, hero). `ease-tokens.test.ts` has a parity test (committed CSS must equal `render()`).
9. **KID-MODE-02 is not built.** No `html[data-mode]` block exists in `tokens.css` and `spec/modes/` does not exist; it will append to the same generator. New type tokens must be written so a later mode block can override them (declare in the generator, not by hand).

## 4. Release process (commons)

1. **Where:** `cd <org>/commons`, `bash scripts/wt.sh start <short-name>` (wrapper over `.github/standards/bin/wt.sh`; `WT_INSTALL_DIRS="core ui spec"`; T2 globs include `spec/ui/*`). Work only in the printed worktree.
2. **Per change:** code + test beside it; bump `ui/package.json` version (each tag is `ui-vX.Y.Z` = package version, e.g. commit `6e2b3b4a` touched `ui/CHANGELOG.md`, `ui/package.json`, source, test, and `spec/ui/schema.json` when a node changed); add a `## [ui-vX.Y.Z] - date` entry; add the `UI-DECISIONS.md` row for any part not in the shadcn registry (new parts only; prop/variant additions on existing parts also get rows in practice, see the VIDEO-UI rows); if a schema node changes, `spec` gets its own tag and bump (`spec 0.1.341 pairs with ui 0.5.520`).
3. **Gate:** `scripts/check.sh` (full: per workspace `bun install`, `bun run lint` = `tsc --noEmit && eslint src`, `bun test`; spec ruff and pytest; `ensure-tag.sh` self-test; spec drift; `@maipai/standards std-v0.3.3` core: secrets, PII, prose, no em dashes). `--pre` = installs, lint, typecheck, standards core (T1, what `wt.sh check` runs); `--docs` = standards core only. UI lint tests that bite new kit work: `fixedColors.test.ts` (no color literals outside `--x:` definitions), `i18nLints.test.ts` + `i18n-baseline.json` (every user string through `i18n._`, baseline only shrinks), `text-opacity-contrast.test.ts`, `hitArea`/`touch-target-floor`, `ease-tokens.test.ts` parity, `vendored-no-remote.test.ts`.
4. **Land:** `bash scripts/wt.sh land` fast-forwards onto commons `main` (push is the natural boundary; no PRs). Then **tag**: `git tag ui-vX.Y.Z <landed sha>` and push the tag (Jesse's 2026-11-01 ruling: sessions cut tags and publish releases themselves; never move a pushed tag). `scripts/ensure-tag.sh ui ui-vX.Y.Z` creates the immutable `../commons-tags/ui-ui-vX.Y.Z` worktree that Home resolves.
5. **Home pin:** in a Home `wt/*` worktree, `bash scripts/pin.sh commons ui-vX.Y.Z` (edits `scripts/check.sh` `UI_TAG`, `backend/package.json`, `frontend/package.json` `file:` paths, lockfiles via `bun install --force`, then lands). Never delete `bun.lock`. Home then adopts the part in its own slice (rule 9b: no Home className on kit parts; `bun run lint:ui-rules`).
6. **Cadence:** one tag per small PR is normal (0.5.516 to 0.5.533 shipped in about two days). Do not batch: Home can pin each independently.

## 5. How a slice lands, and ordering constraints

- A kit slice = one commons worktree, one logical change, tests + Showcase state + `UI-DECISIONS.md` row + CHANGELOG + version bump, gate, `wt.sh land`, tag. Then (separately) a Home pin bump and the Home slice that consumes it.
- Architect gate: a design note + `architect` verdict exists (PRO-LOOK-01 approved). A new token value or part per note 19.7 "gets a design note and the architect gate"; the slice references section numbers.
- Order constraints: (a) pin bump to current before judging anything; (b) additive tokens before parts (parts read them); (c) the art re-value and type re-value are the only non-additive steps and ship behind `data-pro-look`; (d) `PRO-LOOK-LINT-01` (Home) lands right after tokens; (e) VIDEO-UI-01 rev 7 edits `video-player.tsx`/`result-feed.tsx` now: K9 waits for it or rebases onto it; (f) KID-MODE-02 owns the generator's next block: land TOKENS-01's generator change first and tell that session.

## 6. Defaults-unchanged rule (how each guarantee is proven)

- New props default to the value that renders today (`undefined` -> same classes). Each variant gets a test "keeps the default classes" (pattern: `PhoneNav.test.tsx` "keeps the default bar classes and Primary label", `button.variants.test.tsx`).
- New tokens are only added; re-values live in `html[data-pro-look]` so nothing changes until Home sets the attribute (one line in the shell, `useEase.ts`-style).
- Snapshot: `elements/__snapshots__` exist; add a dark/light class-string snapshot per touched part.

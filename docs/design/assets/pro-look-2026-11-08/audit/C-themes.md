## 1. How theming works today

Layers, bottom to top (all in the CSS cascade; React only sets classes and attributes):

1. **Kit `dashboard/css/globals.css`** (vendored shadcn template). `:root` and `.dark` hold the template's neutral oklch set. **The 8 Looks live here**: `.style-<look>` (light) and `.dark .style-<look>` (dark) blocks, 31 hand-set custom properties each (background, foreground, card, popover, primary, secondary, muted, muted-foreground, accent, destructive, border, input, ring, chart-1..5, sidebar-*). All values are literal oklch or hex; nothing is derived inside a block. Navy is the only Look with hex (the original Home palette), the other seven are the shadcn base colors (neutral, stone, zinc, mauve, olive, mist, taupe).
2. **Kit `tokens.css`** (1963 lines in the pin). Re-declares a navy reference palette on `:root` (light), on `@media (prefers-color-scheme: dark){ :root:not(.light):not(.dark) }` and on `.dark` (dark): `--surface-page/card/pane/sidebar`, `--page`, `--elevation-*`, `--tint-*`, `--status-*`, `--hue-*` (light and dark variants), `--profile-accent-*` (6 swatches, 3 sets), `--weather-*`, `--kicker`, `--voice-accent`, `--destructive`. Also the type tokens (`--font-size-title 30`, `-section 18`, `-metric 28`, `-body 13.5`, `-supporting 12`), `--radius-card 16`, `--radius-control 10`, `--radius-pill`, `--radius 12`, the `--art-*` family (`:root`, lines ~1713-1745), reader tones, settings tokens (color-mix of background toward foreground, on `:root, body`).
3. **Kit generated ease block** (`EASE-GENERATED`, `html[data-ease-text|targets|spacing|contrast|motion]`): text steps 100/120/140/160 rewrite the five `--font-size-*` px values and the root font size; contrast "more" rewrites `--muted-foreground`; calm mutes `--hue-*`.
4. **Home `frontend/src/shell/tokens.css`** (712 lines), imports the kit files then overrides: brand cyan `--primary` (`hsl(189 94% 26%)` light, `hsl(189 84% 55%)` dark; written three times: `:root`, the media query, `.dark`), Home `--destructive` (two values, same triple), the destructive and badge tint rules (three selector copies each), shell tones `--shell-main/history/rail/divider/composer-*` declared **on `body`** as color-mix of `--background` toward `--foreground` (light percentages, `html.dark body` percentages, and a third copy under the media query), `body[data-accent=<six>]` mapping `--person-accent`, incognito overrides, phone type rules (px literals at 15/22/19/17), and `color-scheme`.
5. **Runtime switches** (all write attributes/classes, never CSS values):
   - `ui.appearance` (system | light | dark, person scope; optional per-device override `maipai.ui.appearance.device`, `deviceAppearancePreference.ts`, `resolveAppearance`). `useAppearance.ts` always sets a concrete `html.dark` or `html.light` (system resolves through `matchMedia`; listener re-applies on OS change) and sets `meta[name=theme-color]` from `--background`. `appearanceResolve.ts` is the one `resolveDark`.
   - `ui.look` (8 values, default `neutral`). `useLookSetting.ts` reads it, `useLook.ts` toggles `body.style-<look>` and writes `{look, dark}` to the per-browser shell cache (`shellCache.ts`, key `maipai.shell.palette`).
   - Accent: `Person.accent` (6 names: blue, violet, teal, orange, pink, red), `useAccent.ts` sets `body[data-accent]`; tokens.css points `--accent`, `--sidebar-accent`, `--settings-fill` at `--profile-accent-<name>`. This is the "accent setting"; it recolors selected/hover surfaces only, not `--primary`.
   - Ease: `useEase.ts` + `easeResolve.ts` set five `data-ease-*` attributes on `<html>` from the person's `ease.*` settings; kit generated blocks key on them.
   - Kid/child mode: **no `data-mode` token scope exists yet** (only `prompt-bar[data-mode=dock]`). KID-MODE-02 values (body 18, 7:1) are design only; PRO-LOOK note section 5.1 says not to overwrite them.
6. **First paint**: `public/first-paint.js` (same-origin, CSP blocks inline) adds only `html.dark|light` from `localStorage maipai.shell.palette` else `matchMedia`. `firstPaintPalette.ts` (called from `main.tsx`) adds `body.style-<look>` plus the html class before React mounts. Neither paints tokens: surface colors come from the CSS, so first paint is right only because the CSS is keyed on those two classes. `public/theme-debug.html/js` is a read-only diagnostic (reports matchMedia, saved palette, then loads `/` in an iframe and prints `--page`, `--background`, `--foreground`, `--card`, body bg/color).
7. **Look-specific selectors**: none in Home outside `body[class*="style-"]` in the incognito rules. The kit's `studio` token scope (Video/Music Create, ui-v0.5.482+, "near-black and lime in dark whatever ui.look") is a second theme dimension that ignores Looks by design. The old `data-look="studio"` is retired.

### Defects found in the mechanism (these are why the note's items 2-4 matter)

- **D1, the `:root` var() resolution trap.** `--art-foreground: var(--foreground)`, `--art-scrim`, `--art-overlay`, `--art-surface`, `--art-track` are declared on `:root`. A `var()` resolves where it is declared, and the Looks set `--background/--foreground` on `body`, so these resolve against the kit's navy root values, not the Look (the settings tokens file already documents this and declares on `:root, body`). In light themes `--art-foreground` is dark text (foreground), and the scrim is a 78% *page-colored* fade: exactly the "dark text on dark art, hard-coded fade" defect named in note 24. Fix = fixed light-on-dark pair, declared on `:root, body`.
- **D2, the navy surface tokens ignore the Look.** `--surface-page/card/pane/sidebar`, `--page`, `--elevation-*`, `--tint-*`, `--canvas-background` are set only in the three navy blocks. They do not change with `.style-<look>`. Anything built on them (canvas gradient, tints, elevation color) shows navy under Neutral. The new surface-0..2 must NOT be added there; derive them from the Look's `--background/--foreground` on `body`.
- **D3, triple-declared dark.** Every dark override is written three times (`:root.dark`/`.dark`, `@media (prefers-color-scheme: dark) :root:not(.light):not(.dark)`, and Home's `html:not(.light)`). That is 12+ blocks to keep in sync. Because `useAppearance` and `first-paint.js` always set a concrete class, the media-query copies only matter before JS runs.
- **D4, olive.** `.dark .style-olive --muted-foreground` is `oklch(0.58 0.031 107.3)`, identical to the light value, on a dark muted of L 0.286; estimated under 4.5:1. Light taupe/olive/stone muted-foreground (L 0.553-0.58 on L 0.96-0.97) are likewise near or under 4.5:1 (the neutral comment records 0.556 = 4.34:1). The existing contrast test does not check muted-foreground per Look. Verify by measurement before trusting.
- **D5, Home `--primary` is cyan on `:root` only**; each `body.style-<look>` sets its own `--primary`, so inside the app the Look's primary wins (neutral #262626, navy #21a6ff, etc.). The brand cyan only shows for things resolved on `html`.

### What the note needs, and how to derive for all 16 pairs

Rule (note 24 item 1): every new token is a function of the Look's own `--background`/`--foreground`/`--primary` plus the scheme, declared once on `:root, body` in the kit `tokens.css` (so D1/D2 cannot recur). No per-Look blocks. Using `color-mix(in oklab, ...)` keeps hue.

| Token | Derivation (one definition, 16 pairs for free) |
|---|---|
| `--surface-0` | `var(--background)` (page). Dark Looks already sit at L .14-.15 (note guide ~6%); light = white or navy `#f4f7fb`. |
| `--surface-1` | dark: `color-mix(--background, --foreground 5%)`; light: `color-mix(--background, --foreground 3%)` (white-on-white cards need a shadow or this 3% step; Looks have card = white, so `--card` is not usable as a layer). Calibrate so dark lands near 11% lightness. |
| `--surface-2` | dark `--foreground 10%`; light `--foreground 6%`. Replaces `--shell-rail/-history` and `--settings-card/-fill` roles over time (aliases first). |
| `--surface-glass` | `color-mix(in srgb, var(--surface-1) 70%, transparent)` plus `--glass-blur: 24px` (backdrop-filter is applied by the part, not a token). One value set; both schemes inherit. |
| `--hairline` | `color-mix(--foreground 8%, transparent)` (note 24). Replaces `--border` for card edges; `--elevation-hairline` (navy only) retired as alias. |
| `--shadow-glass` | one token, color from `--foreground` inverse: dark `oklch(0 0 0 / .45)`, light `oklch(0.2 0.02 255 / .12)` - the only scheme-split token, declared once. |

| `--accent-app`, `--accent-create`, `--accent-companion` | `--accent-app: var(--primary)` (Look's primary, already contrast-checked as button fill); `--accent-create`: the kit's lime studio accent resolved per scheme (the studio scope already has it; expose as the one name); `--accent-companion`: `var(--person-accent, var(--hue-violet))`.

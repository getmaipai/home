# SPLASH-CHAT-01: Splash as an opt-in chat engine, on vendor Splash 1.4.1

## Problem
The chat model (Huihui Qwen3.8-27B abliterated, IQ4_XS) is a recurrent Gated DeltaNet model. On llama-server the first call of a turn re-reads about 4.7k
tokens (live `hub-diag`: median first-call cache_n 0, prompt_n 4727, 7.1 s prefill, 18 of 20 turns). Home drops the previous turn's volatile block
(messages.ts), so only system+tools is shared and a recurrent model has no checkpoint there. The owner chose a better engine over changing the prompt.

## Measured (Mac Studio, vendor Splash 1.4.1, 2026-10-28)
Huihui UD-IQ4_XS with draft incoai/Qwen3.8-27B-DFlash2, offline, 4 GB SSD cache: A first 5282 prompt tokens, cached 0, 5124 ms; B (diverges after
system+tools) cached 5248, 328 ms; B repeat cached 5280; A again cached 5248, 274 ms. Splash reuses a diverging prefix; llama-server does not.
Probe v8 (same machine, 128 GB, live hub running beside the test): decode of 400 tokens at 59.0, 68.4 and 66.3 tok/s against about 25 to 27 on llama-server;
first token 143 and 72 ms warm, 2190 ms cold. The test Splash was resident at about 695 MB to 1.6 GB (mapped model); live llama-servers hold 25.5 GB (27B) and 5.6 GB (4B).

## Design
1. `ChatEngineId` gains `"splash"`. Opt-in only through `stack.engines.chat.engine`; `auto` stays llama-server. llama-server stays the default and the fallback
   (existing 2-failure fallback, a `chat.engine-fallback` health item).
2. The model is unchanged: the pinned Huihui IQ4_XS and its pinned draft, laid out into the Splash hub cache by `splashStore` (links, no copies). No new download,
   no new model pin. Chat stays uncensored (rule: the engine does not change the model or any age/surface gate).
3. Launch: `splashArgs` with `--offline`, `--max-cache-disk <N>G` (bounded), `--language-only` unless the vision projector is in use, served name, context from
   the chat plan. Admission through the memory governor with the existing Splash footprint estimate; refused admission falls back to llama-server.
4. Two pins, coding unchanged. The chat engine gets its own vendor pin, Splash 1.4.1 (https://github.com/incoai/splash/releases/download/1.4.1/splash-1.4.1-arm64-macos26.tar.gz,
   sha256 5746068dc652a4998267d55b1c6d59b545f1bc1e018131c6d8025022f7000d5c, 78,669,011 bytes). The coding engine stays on the fork `1.3.2-ornith.1` in this item, so
   the 122B coding model cannot break. Moving coding to 1.4.1 and deleting the fork is a separate later item that needs MODE-ENGINE-01's smoke test (1.4.1 serves
   the pinned Ornith-122B MLX model and answers one tool call) and the owner's yes; nothing is deleted here.
5. Engine contract suite (ENGINE-CONTRACT-01) runs the Splash chat wire: streaming, tool calls, usage, cancellation, `cached_tokens`.
6. Privacy row: Splash chat makes no outbound connection (`--offline`, `HF_HUB_OFFLINE`, `DO_NOT_TRACK`); the SSD cache holds conversation prefixes on local disk, bounded,
   under the Stack data dir, and emptied at every engine launch (the oMLX precedent), so temporary-chat prefixes never outlive a restart; the privacy row and `docs/user/privacy.md` say so in the same commit.
   The `splash` option's copy comes from spec copy fields through `describeSetting` (S5).
7. Hardware: the opt-in is refused through `resolveChatEngine`'s `unsupported` hook on machines Splash cannot run on (M3 or newer, macOS 26.4 or later, 36 GB or more, per ENGINE-SPLASH-01).
8. Rule 2: the contract list also covers reasoning separated from content and the thinking limit (the open parts of ENGINE-SPLASH-01); a minor's request sets thinking off.
9. Rule 3: Splash applies the Huihui catalog sampling record on every request. Rule 4: the Splash path supports the one smaller-context restart while a video job is held
   (never below 32768), or hands that restart to llama-server.

## Supersedes
Nothing is replaced in this item. When the later item moves coding to 1.4.1 it supersedes: the "Engine source" bullet in `coding-mode-2026-10-22.md`; the fork pin of MODE-ENGINE-01
(already marked superseded by TIER-HOME-05); and it adds `"splash"` to the value list of `stack.engines.chat.engine` from `chat-engine-comparison-2026-10-17.md` step 1 (this item does that addition now).

## Reuse check
Stack 16bc8ac (`--checkpoint-min-step 0`) measured 4429 of 4451 tokens reused on a same-prefix repeat. Its snapshot lands where the prompt ended, so it does not give a checkpoint at
the system+tools boundary of a diverging next turn. After it shipped, live `hub-diag` still shows first-call cache_n 0 on real turns (parent session, 2026-10-28). The diverging-case
measurement on llama-server with 16bc8ac (A, then B) is an acceptance item below; Splash does it in 328 ms.

## Out of scope
Prompt changes, other engines, shipping (the owner runs ship.sh on the Studio).

## Acceptance
ENGINE-SPLASH-01's bar is met: the pin passes the contract and beats the current engine, measured as the full CHAT-AB-01 run on Splash (child turn, spoken turn with the 3 s first-word bar, both 9-turn memory scripts, safety rows, companion-voice row; replies not shorter, plainer or slower to first text) against llama-server with 16bc8ac
(diverging case, decode tokens/s, peak memory beside the other roles; probe v8). Unit and contract tests pass; Stack gate passes; with the setting on, a real second turn shows a large first-call cache_n in `hub-diag turns`; setting off or an
engine failure leaves chat on llama-server.

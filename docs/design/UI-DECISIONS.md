| `result-feed` (element and `result_feed` schema node, with `poll_while`) | VIDEO-UI-04, 2026-11-02; approved in home `docs/design/video-create-one-page-2026-11-02.md` K9 and K10 (architect APPROVED, revision 7) | A video page needs a newest-first feed of clips with words, tags, a start-frame chip, one player per entry, a filter bar and day groups. `media_shelf` draws tiles that open or play something, not an entry with a live job, a player and per-entry actions; `ActivityFeed` is a log of events with no player, actions or filters; `list` has no player. No shadcn or Kibo part is a bound media feed. It composes the shipped `VideoPlayer` (one per entry, its own built-in Stop, Try again, Make another, draft actions and Favorite, mapped from `handlers`), `DayDivider` (day headings, as `ActivityFeed` uses it), and the shipped `Switch`, `Select` and `Label` for the filter bar; no className override and no Home wrapper. `poll_while` is required because a real run on 2026-11-02 left an entry on a stale line for 3 minutes: a package binding never refetches on its own. Single definition: `ui/src/schema/feedPolling.ts` holds the interval, `FEED_POLL_INTERVAL_MS` = 3000 ms, and the settled set; a row is running when its status is in the page's `poll_while.statuses` (`queued`, `generating`) and settled otherwise (`draft`, `ready`, `failed`, `cancelled`); only running rows' own records (`poll_while.record`) are re-read, polling stops when none is running, and a tab that was hidden re-reads at once when it is shown again. | none new; `VideoPlayer`, `DayDivider`, `Switch`, `Select`, `Label`, `Button`, `AsyncState` | ui-v0.5.466 |

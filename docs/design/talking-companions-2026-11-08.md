# Talking companions (2026-11-08)

## Goal

Move a companion's mouth with its spoken voice. The body remains the approved rest picture while it talks. The audio stays on the existing speech path.

## Rulings

1. While talking, the body stays a still (the keyed rest picture) with a moving mouth. A moving-body talking clip is not built now.
2. Six mouth shapes per character, approved like the rest of the sheet (shape letters A to F, X = rest).
3. Bench MuseTalk now, on one stylised and one human-like character. Needs a model download: ask the owner first.

The scheduler buffers whole sentences with a start time each (`sentenceSpeechScheduler.ts:14-22, 129-150`). - The companion sheet already has a `mouth` view (`backend/src/lib/companionLookJobs.ts:66`), made by a Klein reference edit. Masked edits exist: `edit_masked` with a painted box (`companionLookJobs.ts:168`, `backend/src/lib/imageEdit.ts:338`), through `prepareEditSource` (`companionLookJobs.ts:163`) and the age and child screens.
- The kit `CompanionAvatar` draws clips through a WebGL canvas (`stacked-alpha-video.tsx:102-103`) and has no overlay slot. The `ring` prop is the precedent for an additive prop. Spec vocabulary in `commons/spec/vocab/companion-media.json` has no mouth field; `speaking` falls back to `idle`.
- No TTS engine emits word or phoneme timing. Chatterbox Turbo streams 1 s chunks (`stack/backend/src/speech/mlx_tts_server.py:41, 235-240`), Pocket TTS streams WAV only, and Fish Audio Drama 3 returns a duration only (`stack/backend/src/recordedSpeech/recordedSpeech.ts:30`).
- Stack has an MMS forced aligner (`stack/backend/src/align/align_worker.py`, peak 3.8 to 11 GB, lyrics only, `align.ts:21-23`). Parakeet token start times (`stack/backend/src/speech/sherpa.ts:22`, `transcriptSpans.ts:33`) are a no-download fallback for word times.
- Loki Doki is archived and read only: `frontend/src/components/companion/{phonemeViseme,viseme-scheduler,amplitude-fallback,visemeMap}.ts`. Its phoneme path was never fed; only the amplitude mouth ran (`amplitude-fallback.ts:3-4`). Port `amplitude-fallback.ts:35-65` (syllable rotation) and `VisemeScheduler`; do not rebuild.

## Build design for P2 and P3 (2026-11-09, owner: build it fully, photos and animated characters)

**Data model (one definition: spec first, then the kit, then Home).** The spec defines the anchor shape and the shape-letter keys (`animation.mouth`, `animation.eyes`, below). Home's `look.json` `sheet` gains `talk`, which holds review state, the maker, version ids and this companion's anchor values (typed by the spec anchor), and references those spec types: `{ state: "needs_review" | "approved", maker: "liveportrait" | "crop-edit", anchor: {x,y,w,h}, eyes_anchor: {x,y,w,h}, shapes: { A..F: versionId }, eyes: { closed: versionId, half?: versionId } }`. Anchors are fractions (0 to 1) of the rest picture. Each shape and eye picture is stored as a full-size keyed version like any look picture, and Home serves a small cropped PNG per shape (cut to the anchor, soft alpha edge) at `/api/companions/{id}/talk/{shape}` and `/talk/eyes/{closed|half}`. `X` is the rest picture (no overlay). Spec (`commons/spec`, additive, shipped first): `animation.mouth` = `{ anchor, shapes: { A..F: png } }` and `animation.eyes` = `{ anchor, closed: png, half?: png }`, so catalog packages can ship a talking companion; spec first, then the kit, then Home.

**Kit (`CompanionAvatar`, additive).** The existing `mouth` prop keeps `still` and `level` and gains optional `shapes`, `anchor`, `cue` (a function returning the current shape letter from timed speech, or null) and `eyes`. With shapes present the kit draws the rest still plus one cropped shape at the anchor, chosen by `cue()` when it answers and by level thresholds otherwise. Blinks: after a random 3 to 6 s the closed eye crop shows for about 120 ms (half crop for the first 50 ms when present). They run only while the keyed still is shown (the mouth path while speaking), `animated` true, the page visible and reduced motion off, and never over a playing clip. Only the pane stage and Chat pass `eyes`; the 36 px header avatar does not. The kit draws every crop; Home never overlays a div.

**Makers.** Photos: LivePortrait on the Stack (a managed uv environment and worker like `image-tools`; MIT code and weights pinned by revision and checksum; MediaPipe or Apple Vision face boxes replace the non-commercial InsightFace detector; a pinned `landmark.onnx` is MIT-licensed or replaced). Stack route: one rest picture in, mouth ratios and eye ratios in, PNGs out (about half a second each on the GPU). Stylised and animated characters: the mouth-crop masked edit from the spike (Home, through `edit_masked`, no face swap, no fit, style "keep", fixed seed, colour match, feathered paste), using anchors from a vision-model box request that the person can nudge in the sheet step. Both makers keep `prepareEditSource` and the age and child screens. Animated characters here means cartoon, anime and stylised characters; the idle video loop is not touched: while speaking the kit shows the keyed still with the crops (the TALK-01 behaviour), and the loop returns when speech ends.

**Timing (P3, changed 2026-11-09).** Rhubarb Lip Sync is dropped: its macOS release is an Intel-only binary (verified, `Mach-O x86_64`), this Mac has no Rosetta and no admin access to add it, and building it needs Boost. Instead the Stack's existing recognizer gives word times: a new Stack route `POST /v1/audio/mouth-timings` takes one sentence of speech audio (WAV) plus its spoken text and returns `{ words: [{ text, start, end }] }` from the Parakeet token times already turned into words by `wordsFromTokenTimes` (`stack/backend/src/speech/transcriptSpans.ts`); no new model, binary or licence. Home turns each word into shapes in three steps and spreads them across the word's span: (1) letters to ARPAbet phonemes through the CMU Pronouncing Dictionary (npm `cmu-pronouncing-dictionary` 3.0.0, ISC licence, downloaded by the package manager, not vendored; Rhubarb itself uses this dictionary), with a plain letter rule only for words the dictionary lacks; (2) phonemes to Loki Doki's viseme ids through the ported `IPA_TO_VISEME` (`phonemeViseme.ts`, with ARPAbet keys added); (3) viseme ids to shapes A to F through a new, small, hand-built table (about 15 rows; no shipped table fits because Loki Doki's `visemeMap.ts` maps to eight DiceBear mouth names, not A to F, so that file is not reused); `/api/tts` returns per-sentence cues; the browser maps cues to the AudioContext clock (`VisemeScheduler` ported). The first sentence starts on level thresholds; any failure (recognizer busy, no timestamps, route down) falls back to levels and never fails the answer. Words are matched to the spoken string, not the written text. Parakeet is the optional recognizer; the default is Moonshine, which most likely returns no timestamps, so on a default install timed shapes do not run and the mouth stays on levels (TALK-09 checks which recognizer this hub runs and, if needed, says so in the report).

**Status (RULE S6).** No new surface. Sheet-step jobs use the existing job card; the Make button is disabled by `useMakingAvailability` on the `image` row; the LivePortrait engine reports through the Stack's engine health rows.

**Slices and order:** TALK-04 spec and kit (commons), TALK-05 Home sheet step with the crop-edit maker, anchors and serving, TALK-06 Stack LivePortrait engine and route, TALK-10 Home wires the LivePortrait maker (after TALK-06), TALK-07 Stack mouth-timings route, TALK-08 Home timed cues, scheduler and blink wiring, TALK-09 verify end to end on a photo companion and a stylised one, then ship.

## Light at play time, and idle life (owner ruling, 2026-11-09)

Owner rulings after the first demos: speaking must cost almost nothing in memory and CPU, for photos as much as for cartoons; the head must not look frozen; a character should have several idle movements that cycle, so it feels alive.

**Play time is sprites only.** Nothing generates at play time. The heavy work (the picture engine's masked edits, LivePortrait) runs once, when the character's talk set is made, and its output is cut into small pictures. Measured on the cartoon test character: six mouth crops of 102 x 77 px at 14 to 16 KB each, two eye crops of 261 x 102 px at 58 to 61 KB each, 209 KB in total as PNG and about 0.4 MB decoded. The kit swaps these over the one rest picture (a handful of `<img>` opacity writes per frame) and moves the whole figure with a CSS transform: no model, no video decode, no canvas pipeline. A photo companion costs the same, because LivePortrait's frames go through the same step as the picture engine's edits: only the patch inside the anchor ellipse is taken, colour-matched to the ring around it and pasted onto the untouched rest picture with a soft edge, then cut to the anchor box. A looping animated GIF or video would cost more (every frame decoded and kept), not less, and cannot change a mouth per sound.

**Timing needs no recognizer (changes TALK-08; TALK-07 stays as an optional upgrade).** Default timed shapes are computed in the browser, with no Stack call: the spoken text goes to phonemes through the CMU Pronouncing Dictionary (ISC, npm; letter rule for unknown words); each vowel is a mouth-opening nucleus; the nuclei are aligned monotonically (dynamic programming) to the energy peaks of the sentence's audio level envelope, which the level meter already reads, and consonants (closed lips for P B M, pursed for W, round for the OH sound) are placed between nuclei. Cost: a few thousand arithmetic steps per sentence. The Stack word-times route (TALK-07, landed) is only used when a recognizer that reports word times is running and a person has turned the better timing on; it is never required, and the default Moonshine recognizer is not needed. The person's switch for the better timing is a spec settings registry key first, with its copy from `describeSetting`; whether a timing recognizer is running is read from `/api/health` (its one readiness function), never by a client probe or a new polling loop. Any failure falls back to levels. The first sentence starts on levels.

**Idle life (new TALK-11).** The speaking figure already breathes, sways and nods (ui 0.5.557, `mouth.life`). Idle gets a cycling repertoire of small movements, chosen at random with no repeat in a row, each 2 to 5 seconds eased in and out with 1 to 4 seconds of stillness between: head tilt left or right (a sideways roll only, never a pitch toward the viewer); look-around sway; slow nod; a lean back or settle (never a lean toward the viewer, which is the `needs_you` and `listening` look, and idle must never look like listening); shift; double blink and slow blink; a micro-smile (the B shape for about 600 ms then A, only when a mouth set exists); and, when the character has extra eye pictures, a glance left or right (optional eye poses `look_left` and `look_right`, made by the same maker as the blink pictures, one extra edit each; LivePortrait gives photos the same through eye-direction parameters). The sequencer replaces, and does not run beside, the kit's existing idle timer in `companion-avatar-machine.ts` (`idle_look` every 20 to 40 s with an injectable `random`): in still mode the procedural glance takes the place of the `idle_look` clip, so the two never both play; the robot's `bot/body/maipai_body/expression/idle.py` (a pure, clock-injected micro-pose policy with still, calm and lively levels) is the reference. The sequencer is a pure function of a seed, so it is deterministic in tests; the repertoire honours the ambient record's idle-animation setting alongside reduced motion and `animated=false` once that setting's key exists; every move is a CSS transform or a sprite swap, so it costs nothing in memory. A character with an approved talk set may use the still plus this repertoire instead of its idle video loop (a video loop is decoded video: the heaviest thing on the stage); a character without a talk set keeps its loop. The extra `look_left` and `look_right` pictures are companion media: each goes through `prepareEditSource`, the child and teen finished-item checks and the adult CSAM check, and a check that cannot run fails closed (rule 10). This narrows the idle row and the `idle_look` row of the video-characters record (see Supersedes).

## P2-spike result (2026-11-09)

Run on a real-person photo companion (the plan said the dev seed companion; the "Open" line below still asks for a stylised character before the sheet step is approved).

- **Home's normal edit route cannot make a mouth shape.** `startLookEdit` with a mask runs a head swap (`faceRef`, `swapHead`) that copies the rest picture's face back over the edit, and it appends the version's style phrase ("cartoon"), which redraws the mouth as a cartoon. Its fit and key steps also rescale the picture, so the result no longer lines up with the rest. Six shapes through it showed no mouth change.
- **One full-frame masked edit drifts.** The mouth changes but the eyes and expression change too (smile creases lost).
- **A mouth-only crop edit works.** Crop a 384 px square on the mouth, upscale to 1024, masked-edit it with no face swap, no fit, style "keep" and one fixed seed, and paste back only a feathered ellipse onto the untouched rest, taking the edited crop from the engine's raw output (the `.orig.png`), not the keyed version. Measured: the raw crop lines up with the rest at offset 0 and scale 1. Shapes A, B, C, D and F were distinct and the same man. Moustache edges are still soft and shape E ("oh") came back as a smile.
- **LivePortrait beats the crop method on a real photo (bench, same day).** One photo in, a mouth-open ratio and an eye-open ratio out. Same pixels in every frame, so teeth, lips and identity stay put; five mouth steps and a blink each took about half a second on this Mac's GPU. Its code and weights are MIT, but its bundled face detector (InsightFace buffalo_l) is non-commercial: a shipped version needs a licence-clean detector (MediaPipe) first. Stylised characters are untested. A first bench run produced garbage because the zoom argument was passed as 0; its default is 1.
- **Open:** a better prompt for E, and a check on several faces and one stylised character before the sheet step is approved.
- **Eyes:** blinking is the same technique on the eyes (one closed-eyes picture, optionally half closed). It is added to TALK-02's scope; the decided design is in "Build design for P2 and P3" below.
- **Design of the job is left to TALK-02's own reuse check.** That check must start from LIKENESS-01's face scope (`backend/src/lib/pictures/likeness/edit.ts`: ellipse mask, `editMasked` with Stack feathering and paste-back, several seeds, identity check) and say what it reuses and what is new. Any new route must keep `prepareEditSource` and the age and child screens that `startLookEdit` applies.

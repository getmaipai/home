## V1 Voiceover

1. **One tag definition.** `backend/src/lib/recordedTags.ts` is the only place that says which bracket tags an engine can speak. Chatterbox Turbo: the names Home already verified by ear (`KNOWN_CUE_TAGS`) that the Stack's `tts` role advertises now (`getTtsTags`), so a Stack that advertises none gives none. Fish Audio Drama 3: a fixed list read from its model card and technical report (`[sighs] [laughs] [whispers]` on the card; `[gasps] [coughs] [clears throat] [pause] [softly] [hesitates]` in the report). Only tags found in those two documents are offered; the engine takes free-form directions, so this is the documented floor, not a limit it enforces. It lives in the backend and reaches the page through the options route (the page keeps no copy). It moves into `@maipai/spec` the first time the robot or Go needs it (additive, spec first).
2. **Which engine will speak.** `plannedRecordedEngine(voice)` in `lib/tts.ts` answers with the same test `synthesizeRecordedSpeech` uses to pick Fish (a household clip voice with a stored transcript while the recorded engine is installed and ready) and says Chatterbox otherwise. A per-render fallback to Chatterbox drops a tag Chatterbox cannot speak in `synthesizeSpeech` (REG-02), so a tag is never read aloud; the record and the card say which engine really spoke.
3. **Make it.** `lib/voiceover.ts` `makeVoiceover(actor, { script, voice })`: length 1 to 2000 characters; `videoRefusalFor` on the script (the one text floor the Studio uses; for an adult the CSAM check only); the voice by `voiceChoice` after one shared function `voicesFor(actor)` that keeps a minor to presets and the engine default (the options route and `makeVoiceover` both call it; never a clip voice until V4); `synthesizeRecordedSpeech`; the result is a Library audio file written by `storeFile` with no conversation (the Library upload path), provenance `voiceover:{"v":1,"engine","revision","voice","kind":"preset|clip"}` (principle 3, VOICES-06), and `"voiceover"` added to the Library writers so it lists as made by Home. The file name is "Voiceover" plus the date; the script is never stored or logged.
4. **Routes.** `GET /api/voiceover/options` (voices this person may pick, each with `engine` and `tags`) and `POST /api/voiceover` (script, voice; answers the file id, seconds, engine, voice and kind). Signed-in members only; a failed render answers one plain line (S6), never a raw error.
5. **Page.** The Music Create bar gets a Voice chip beside Song, Band, Album and Style (the page is adult only today, so a minor does not reach it; the route itself already holds the minor rule for chat). The Voice body is its own file (not named *Panel or *Card): a two-way switch (kit segmented control) (Voiceover, Change voice; Translate is absent until V3 passes its bench), the voice picker (kit `Select`), the script box (kit `Textarea`) with the tag chips of the picked voice's engine, a kit `Button`, and the result in the kit audio player with the engine line and Open in Library. Kit parts as shipped, no className on a kit element (rules 9, 9b). Checked at 1440 and 390.
6. **Chat half.** A conditional tool `voiceover` (an adult on their own screen; offered on the `voice` row of `roleHealth`, not the music engine) with its bench rows (a positive, a negative, a minor refusal). The model decides when; the tool takes the script, an optional voice name and makes the audio file only. A voice over a clip in view stays `edit_video` mix (`sound: "voice"`); `voiceover` never lays audio on a video, so the model has one tool per effect. The offer set stays at 16 or fewer: `voiceover` joins the music shrink order.

## V2 Change voice

1. **Source.** A Library file the person owns, audio or video (the page uploads through the existing Library upload and passes the id; nothing leaves the home). A video clip made here comes in by its Library file the same way. The source follows the song-remix owned-file rule: read only through `readAttachment` for its owner.
2. **Steps.** Transcribe with the Stack `stt` role (`transcribeAudioClip`), speak the text in the picked voice (`makeVoiceover`'s speak step), fit the spoken length to the source length, then for a video mute the picture's own sound and lay the new voice from 0 with `media.edit` (`mute` then `audio_overlay`, through `runStackEdit`, the one audio-on-clips path Videos owns); for audio the result is the spoken file. Same timing here means the same sentences in the same order over the same clip: the Stack's `media.edit` writes only mp4, mov or png, so the spoken file cannot be time-stretched on its own; a voice longer than the clip is cut at the clip's end (`audio_overlay` `end_s`), one shorter leaves silence at the end, and the result says in one plain line how many seconds the new voice differs by. Stretching to fit and per-sentence alignment wait for the Stack to return segment times and an audio-only edit.
3. **Rules.** Existing voices only (V4 is not here); **a minor is refused** (parent note section 4: a minor's Change voice is refused until a named later row exists), by the route and by the tool, with one plain line; the transcript is held in memory for the length of the request and dropped, never stored or logged (rule 6a); the text floor runs on the transcript before it is spoken; the result is a Library file with the same `voiceover` provenance plus `"source"` (the Library file id) and `"kind"`. The original is never changed.
4. **Page and chat.** The second switch position: pick the file, pick the voice, Make. Chat tool `change_voice`, gated and benched like `voiceover`, with a minor-refusal bench row; both tools together keep the offer set at 16 or fewer.

## Status (rule S6)

A Make button reads the `voice` (tts) row of `roleHealth` through `/api/health` (S6: one readiness function, never recomputed by the page) and, when it cannot work, says why beside it. A failed render uses the S6 "a form or action failed" row, one plain line; the POST answers with the file id directly, so there is no job record. A tool whose bench has not passed is absent from the offer.

## 0. What exists today (read from origin/main, 2026-10-18)

## 1. What can ship in the box

### 1.1 Engine fact that decides everything

mlx-audio 0.5.9, `ChatterboxTurboModel.generate(text, ref_audio=..., ...)` takes a path or an array. `prepare_conditionals` requires more than 5 seconds of
audio (assertion), normalizes loudness, uses at most 10 s for the decoder and 15 s for the voice encoder, runs S3TokenizerV2, the voice encoder and the
S3Gen embedder, and then **overwrites `self._conds`**. Two consequences:

1. A reference clip must be 6 to 30 s (10 to 15 s is the sweet spot; longer is trimmed by the model).
2. If the Stack's engine calls `generate(ref_audio=...)` per request the first reference voice replaces the default for every later request and the
   engine re-derives the conditioning every time. The Stack must hold a `Conditionals` per voice (the class has `save`/`load`) and set `_conds` before each
   job, restoring the default after. This is an engine change, not a Home change (section 4).

`S3TokenizerV2` (472 MB, `mlx-community/S3TokenizerV2`) is not pinned today; `post_load_hook` tries to download it, and `_extract_conditionals` logs "S3Tokenizer
not available - using fallback" instead of failing. A fallback that silently conditions on nothing would make every voice sound like the default, so the Stack
must pin the file by sha256 and a test must prove the tokenizer loaded.

Rules every slot must pass before it ships (VOICES-02's gate):
- Adult and clearly not child-like: median F0 for the clip is measured (adult female speech is below about 260 Hz median; the screen rejects above it and
  anything a listener hears as young) and Jesse or a parent listens. No clip is accepted on a metric alone.
- No identifiable real person: donation ids are anonymous; a clip that names the speaker or says a name is rejected; STT transcript is read for names.
- One speaker, one clean 10 to 15 s take, no music, no clipping, noise floor checked; prefer the `_enhanced` copy only if it sounds clean.

**Size.** A reference clip is 0.48 to 1.2 MB. The eleven clips are about 6 MB; the S3Gen conditioning for all of them, cached, is a few MB more.
The one real install cost is the S3TokenizerV2 file, 472 MB, once, shared by every voice and by cloning. Total new disk for the whole feature: about 480 MB.
Pocket's 26 presets stay about 160 MB on small machines and are only downloaded on first use of each.

### 1.4 Do voices have to be re-measured for tags and emotion?

Yes, per voice. Slice 1 measured the six tags with the default conditioning only (voiced fraction and spectral flatness against spoken words, three runs).
Chatterbox conditions on the reference for timbre, rhythm and style; a flat or whispery reference can make `[laugh]` or `[sigh]` come out weak or spoken. So each
shipped voice carries its **own** tag list. The wire already allows it: `Voice.tts = { engine, tags }` is per voice, and the composer (REG-02) writes only the tags listed
for the voice in use. A voice that renders fewer than three tags keeps those it passes; one that renders none is still allowed (plain speech is fine). Emotion: the Turbo model has no
exaggeration control (`prepare_conditionals` says "not used in Turbo"), so emotion comes from the reference and the text; the ear test notes a one-line register per voice.

### 1.5 Listening test plan (not run)

I did not run it: it needs about 20 reference clips downloaded from Hugging Face (needs your yes, about 15 MB) and the GPU. Also, the plan cannot go "through
the live Stack's `/v1/audio/speech`" today, because the live engine ignores `voice_url` (section 0). The live route only proves the default voice. Per-reference samples need
a scratch engine process until VOICES-02 lands.

Protocol, per candidate, one request at a time:
1. Take the GPU lock without waiting: `mkdir /private/tmp/claude-501/bench.lock`. If it exists, skip and try later. `rmdir` it when the request ends, even on failure.
2. Start (once, under the lock) a scratch copy of `mlx_tts_server.py` on a spare port, using the live engine's Python
   (`/usr/local/maipai-home/stack/data/engines/mlx-audio/0.5.9/venv/bin/python`, read only), patched in the scratch copy to call
   `generate(ref_audio=path)` and to restore the default conditioning after. Never edit the live script. The live Stack is not restarted.
3. Text per candidate: three tiny strings (under 12 words each): a plain sentence, one with `[laugh]` and `[sigh]`, one with a number and a name ("Clover, the kitchen light is on at 7:30.").
4. Save WAVs to the scratchpad `voices/wav/<slot>__<n>.wav`. Time first audio and total with a wall clock; run each text twice (cold conditioning, then cached).
5. Transcribe every WAV through the live Stack's STT (`POST /v1/audio/transcriptions`) and score word error rate against the text with tags removed. Pass: at most 10% on the plain
   sentence and at most 20% on the tagged one. Anything else is "not intelligible enough".
6. Tag test: the slice-1 method (voiced fraction, spectral flatness, three runs per tag) on each shipped voice. Record the passing tags in the voice's manifest.
7. Jesse's ear: a single folder of the survivors, a pass or fail per voice, and the label. Nothing ships on a metric alone.
8. Report: a table of voice, source id, WER, first-audio cold and cached, tags passed, Jesse's verdict. Memory: record peak RSS with two and with eleven voices cached.

### 1.6 Latency cost per voice

Unmeasured. Reasoning from the code: conditioning is paid per call today (`prepare_conditionals` on every `generate(ref_audio=...)`: loudness normalization, two
resamples, S3Tokenizer on up to 15 s, voice encoder, S3Gen embedding of up to 10 s). With a cache keyed by the clip's sha256 the cost is paid once per voice per engine start, and the
warm-up at boot can pre-condition the household's chosen voices (the prime pass already costs 6 to 14 s). The step 5 numbers decide. Acceptance (VOICES-02): cached first audio within
0.1 s of the default voice's 0.45 s on the Studio; a cold first use under 3 s, otherwise the first sentence of the first reply after a restart is spoken with the cached default and
the voice is warmed in the background (S6: the engine's state, not a new banner).

## 2. Admins install more

### 2.1 Two ways to add a voice

**A. A voice pack from the catalog** (no consent question: the pack is a published, licensed voice).
- `getmaipai/catalog` `voices/<pack-id>/` uses the existing `voice` kind. The manifest lists voices: `id`, plain `label` and `detail`, the clip (`clip.wav`, 6 to 30 s,
  sha256, size), `licence` (an SPDX id), `attribution` (required for CC-BY), `source` (dataset and id), `audience` (`all` or `adult`), `tags` (measured), a `sample.wav` and the
  engine it was measured on. Packs are signed and indexed like every package (TUF-style `targets`, hash and size, per PACKAGES.md); a pack with no licence or with a non-commercial licence fails
  the catalog check. A pack that names a real person fails the check unless it carries a consent file (a signed statement, kept in the pack, not in the manifest text).
- The starter set is one pack, `starter-voices`, bundled in the Home release (like the bundled apps) and installed to the Stack at setup. It can be uninstalled (an admin) and reinstalled.
- Community packs follow catalog rules: the only repo that takes pull requests, with the signed copyright assignment (LICENSING.md), plus the voice rules above.
- Home passes the clip to the Stack (section 4); the Stack stores it by sha256 and lists it. Nothing is fetched at speech time (offline always, PRIVACY.md).

**B. A voice made from a recording** (the consent path, section 3). Not a catalog item. An owner or admin records, or adds a clip of, a consenting adult household member (10 to 30 seconds); the speaker confirms in their own session before it is usable. An admin may be the speaker.

### 2.2 Where it shows

- **Voice page** (Settings, Voice; today `VoiceBrowserSection`): the same one `Select` and Test, with the options grouped: *Standard*, *Starter voices*, *Made from a recording*.
  Everyone picks from it (a child or teen sees the curated subset only; a child still has a guardian choose). Beside Test, **only an owner or admin** sees **Add a voice** and *Voice packs*; a member or teen sees neither, and the add routes refuse them with a 403. Each option shows its label and detail. Test plays the Stack's cached preview
  (STACK-101c already does this per voice id; the cache path currently special-cases the default id and must key on any id).
- **Models and storage** (COMPONENTS-01): group `voice` gets one row per pack ("Starter voices, 11 voices, 6 MB, Installed. Used by: the Voice page") with Install and Uninstall and the pack's licence
  and attribution shown through the existing licence notice; and the S3 tokenizer as a required part of the Chatterbox row, not a row of its own. Voices made from recordings are people's data, not
  parts: one read-only row "Voices made from recordings" with a count and size and the line "Remove one on the Voice page." Uninstalling a pack someone has selected sets those people to Standard with the
  existing VOICE-PICK-01 migration line ("Your voice was set to Standard because ... was removed"), nothing else.
- **Per-person default** already exists as `tts.voice_id` (person scope). A new person starts on Standard. A household default is not added (one more setting with no ask behind it).
- **Per age band.** Each voice has `audience`. A child's and a teen's list is the `all` subset (curated by the VOICES-02 listening gate), never a voice made from a recording, and a guardian still chooses for a child
  (VOICE-BROWSER-01D unchanged). Today's refusal for a child of any non-preset voice generalises to "any voice not marked `all` or any clone".
- **Test per voice**: exists; keep. A person who cannot install still hears Test for the voices on disk.

## 3. Safety: a cloned voice is a likeness

### 3.1 Absolute lines (proposed addition to SAFETY.md, needs Jesse)

0. Only an owner or admin creates or installs a voice (owner ruling 2026-10-18). A member, teen or child cannot, and the routes refuse them.
1. No voice is made from a recording of a person who has not agreed to it. The agreement is the speaker's own, recorded in their own session before the voice is usable.
2. No voice of a minor, ever. The speaker must be an adult household member (the same test as the likeness subject: role owner, admin or adult and a birthdate-aware adult band; not a guest, not a memorial profile). A voice is offered to a child or teen profile only if it is a curated starter or pack voice marked `audience: all`, never a voice made from a recording.
3. No public figure, and no real person outside the household, whatever their consent in a file.
4. Who may pick a voice made from a recording is the speaker's choice: by default only the speaker. The speaker may switch on "Let other adults here use my voice" (a person-scope setting, off by default, only the speaker writes it, like `likeness.adults`); a child or teen never picks it. This is wider than the earlier draft, which had no sharing at all, because the ruling lets every member pick installed voices; the switch keeps the speaker in control. Turning it on needs the `/api/tts` binding in section 3.3 first (VOICES-08), so until then the default stays speaker-only.
5. The speaker can remove it at any time (also an admin); removal deletes the clip and conditioning, sets anyone using it to Standard, and writes a dated record.
6. A cloned voice never speaks adult sexual content. The text floors already run on every spoken sentence (RULES.md, spoken turns); a sentence they class as adult is spoken in Standard instead, and the written reply is unchanged. Test row required.

### 3.2 Consent, reusing the likeness design

What the likeness code gives us (`docs/design/likeness-consent-2026-10-17.md`): consent is a setting only the subject writes, off by default, an owner or admin may only turn it off,
every change appends a `LikenessConsent` record (id, option, state, source, clock stamp), consent is read live and never cached, a subject is a living household adult, and the Stack
checks an Ed25519 proof signed by Home, bound to the file's sha256, used once, at most 30 minutes (`lib/likeness/proof.ts`, Stack `lib/likeness.ts`). All of that carries over.

Where voice differs: likeness pictures are made from a photo or a style the requester holds. A voice is made from audio the requester holds, so "uploaded clip of someone else with a tick box"
would let one adult clone another with nothing checking. So:

- **The cleanest flow inside the ruling (recommended): the admin records the speaker live in Home, the speaker confirms in their own session.**
  1. An admin opens Add a voice, picks the household adult, and either records them live (the speaker reads the agreement phrase of section 2.3 aloud into the admin's device) or uploads a clip.
  2. Home transcribes the clip with the household STT and, for a live recording, checks the agreement phrase and the speaker's first name. An upload has no phrase, so it always takes the confirmation in step 3. The voice is saved with status `pending`, unusable by anyone, not even for Test by the admin.
  3. The speaker gets a notification (Notifications, the bell, audience: that person) and, in **their own signed-in session**, plays the clip and presses "Yes, I agree". Only then does the voice become `active`. "No" deletes it. The consent is a record written by the speaker's own action, not by the admin, mirroring how only the subject writes `likeness.adults`. When the admin is the speaker, the admin's own confirmation still happens in the same flow as a separate explicit step.
  4. A pending voice that is not confirmed in 14 days is deleted with its clip. The admin is told.
  This is the likeness design's rule carried over: an admin may withdraw consent on someone's behalf (remove) but never grant it. It also answers the weakness of an upload with a tick box: the person in the clip must say yes themselves, signed in as themselves.
- Child, teen and guest accounts cannot be the speaker. If the clip's speaker sounds like a child the admin cannot tell either way; the lines rest on the admin's attestation plus the adult-only picker, and the confirmation step is a second human check. A voiceprint comparison (VOICES-06) adds a third.
- The clip length is 10 to 30 s after trimming silence; under 6 s is refused (the engine's limit), over 60 s is trimmed.
- A new spec record `HouseholdVoice` (spec first, then Home, per the platform principle): `id`, `label`, `kind` (`starter`, `pack`, `recorded`), `subject_person_id` (recorded only), `source` and `licence` (packs),
  `clip_sha256`, `created_by` (the admin), `consent` (speaker's confirmation time, phrase text and transcript for a live recording, `source: "settings"`), `status` (`pending`, `active`, `removed`), clock stamp, provenance. Append-only history of removals like `LikenessConsent`.
- Existing `cloned_voices` rows (Pocket-era uploads) have no consent and may include any speaker: on migration they are **hidden from the Voice page and not offered** (status `needs_consent`); an admin sees them listed and can delete them or start the speaker's confirmation (section 3.2); a non-admin creator sees nothing. Nothing is deleted without being listed first (Clean up on sight: list, do not delete other people's data).
- `POST /api/voice/cloned` gets a role gate (owner and admin only; today it has none and a child can call it), and so do pack install and uninstall.

### 3.3 Finished-audio check and provenance

- **Text floors are the check we have.** Every spoken sentence goes through the floors for a child and for any spoken turn; they run before synthesis and do not depend on whose voice it is. I found nothing that
  inspects finished audio for sexual content (the music note names the same gap, MUSIC-GEN-15 for sung words). A post-render STT check on a clone's output costs one STT pass per sentence; v1 does not add it because the text path already
  decides what is said and the voice cannot change the words. A named gap, not hidden.
- **Arbitrary text is the real risk.** `POST /api/tts` voices any text up to 4,000 characters in the caller's voice. In v1 a clone is chosen only by its speaker (3.1 line 4), so the worst case is a person speaking their own voice. If sharing a voice with other adults is ever added (not in this design), that route must bind
  speech to a turn's own reply text first. Recorded as a precondition on any sharing slice.
- **Watermark.** The upstream Chatterbox package always applies Resemble's PerTh watermark; the MLX port has none (checked 2026-10-17). Adding PerTh means PyTorch in the voice environment (several GB), which the MLX engine deliberately avoids. Not feasible for streamed speech on this engine. Feasible and proposed
  instead: any speech saved as a file (a story, a read-aloud download) carries `file.provenance.generation` with `engine`, `voice_id` and `voice_kind` (the MUSIC-SPEC-01 shape), and the voice's own record names its subject and consent. Streamed playback has none. Said plainly on the Voice page: "Voices made from recordings are for you. Home does not mark the audio it plays."
- **Stack proof.** `POST /v1/voices` (section 4) requires a Home-signed proof bound to the clip hash, so no other caller can put a reference clip on the engine, and revoking consent deletes the Stack's copy.

# Stories: bedtime stories, storybooks and read-aloud (2026-10-17)

Design note, written in the 2026-10-17 design audit. The hub ships `bedtime-storybook` (a `project` package: three chapters
written in the background, PROJECT-PACK-01 and PACK-02 built) and `storytime-style` (the one real `skill`, a Claude-format
style the prompt composes in). Both work from chat and nothing shows a child the stories they already have. The kid-mode
note of the same day owns how a child's screen looks and reads; this note owns the feature. Rules in [RULES.md](RULES.md)
and `SAFETY.md` govern; nothing here asks for a rule change.

## Purpose

A child asks for a story and gets one, in one reply or as a storybook with chapters; the family keeps the ones they love and
can hear them read aloud by the house's voice at bedtime with no screen. That is the whole feature. No marketplace of
stories, no characters store, no reading-progress gamification.

## Users and gates

| Person | May |
|---|---|
| Child | ask for a story or a storybook; open their own shelf; play a story aloud; mark a favourite |
| Teen | the same; a teen's stories are their own |
| Adult | the same for themselves; delete their own; set the bedtime voice and the chapter count for a child; a child's shelf is the child's own, shown to a parent only by the child's own act (NO-CROSS-USER-VISIBILITY-01) |
| Admin | nothing extra beyond parenthood |

Rule 0 and SAFETY.md: a child's story is a minor turn with the band's topic block, the content ceiling and the sentence-gated
floor (rule 10) on every chapter, including chapters written in the background; the project runner passes each chapter through
the same output gate before it is stored, never only at display time. Family stories (Santa and the rest) follow the parent's
setting. A story read aloud is a spoken surface: no reasoning, no length past the spoken limit per chapter, the sentence gate.

## Screens and IA

Stories is a section of the Home rail's Library app for minors (kid mode decides its look) and a shelf in Library for adults
(S1: no second rail entry; S2: the Library emulates Apple Books).

1. **Shelf** (`/library/stories`): covers (the kit's media grid; a cover is the first picture if PICTURES-02 made one, else
   the kit's project icon from `spec/vocab/project-icons.json`), newest first, a Favourites row at the top when any exist.
2. **A story** (`/library/stories/:id`): the title, the chapters as the kit's markdown text (rule 9's renderer, reused outside
   chat as the Library already does), a Play button that reads the current chapter with the household's voice (the existing
   `/api/tts` path, the heard-prefix rule on interrupt), Next chapter, Favourite, "Another like this" (a new project with the
   same topic and the same recurring characters, PROJECT-PACK-02).
3. **In chat:** unchanged; a storybook project stays visibly alive (PROJECT-PROGRESS-01) and its done value links to the shelf.
4. **Bedtime** (a one-tap mode on a story): the screen dims to the kit's reading theme, plays the chapter aloud, and stops at
   the chapter end with no autoplay of the next; a parent sets how many chapters a bedtime plays (`stories.bedtime_chapters`,
   default one).
5. **Phone:** the shelf as a two-column grid; a story as a single column; Play in the kit's media bar.

## Data and spec records (spec first)

- `project` (exists): a storybook is a project of type `bedtime-storybook`; its `artifacts` are the chapters as `artifact`
  records (exist). **Addition, spec first:** `artifact.favourite: boolean` (person-scoped, default false) and
  `project.characters: [{name, trait}]` promoted from the package's own outline into the spec shape so "another like this"
  and the robot can read them (principle 3; the robot can tell the same story offline).
- Settings keys (spec first): `stories.bedtime_chapters` (user override set by a parent), `stories.voice` (per person, one of
  the installed voices; a child's set by a parent).
- The `storytime-style` skill stays the one style; a second style is a catalog package, never a setting.

## Offline and privacy

Fully local: the writer is the chat role, the voice is the TTS role, the shelf is the person's own records. No outbound
connection, no privacy row. A story written for a child is the child's record; nobody else opens it unless the child plays
or shares it (NO-CROSS-USER-VISIBILITY-01), and never through a log (rule 6a).

## Kit Elements and parts (rule 9, 9b)

The kit media grid and `card` for the shelf, the kit `MarkdownText` for chapters, `button`, `toggle` (favourite), the
kit media bar for Play with the existing voice path, `sheet` on the phone. No new kit part; no hand-drawn book page.

## Slices

1. **STORIES-01 (S, spec first):** `artifact.favourite`, `project.characters`, the two keys; pin bump.
2. **STORIES-02 (S):** the shelf and the story page from `GET /api/projects` filtered to the type; Favourite.

## Legacy verdicts (rule 8, one line each)

- Legacy "Storytime" app with a character creator and purchasable packs: **dropped**; characters come from the story itself.
- Legacy read-aloud with a third-party voice: **rebuilt** on the house's own TTS role.
- Legacy "reading streak" badges: **dropped**; nothing in Home nudges a child to use it more.
- Legacy "Watch and Listen Together": **not stories**; a media verdict for the media blend note.

## Supersedes

Nothing. It gives the two bundled packages a shelf and a bedtime mode; it changes no project runner behaviour except the
written requirement that background chapters pass the output gate before storage, which PROJECT-PACK-01's runner already does
through `refusePackageReplyIfUnsafe` and this note makes a tested requirement.

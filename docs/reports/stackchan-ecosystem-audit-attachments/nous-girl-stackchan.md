# Audit: nous-girl-stackchan

Read-only audit of a downloaded clone (nothing run or built). [unverified] marks inference.

## 1. What it is
- "Nous-Girl" by Alex Covo (dax8it): custom StackChan K151 (CoreS3, ESP32-S3, 16 MB) firmware snapshot v3.6.7-dj7 (2026-10-28) + "patched server" add-ons for xiaozhi-esp32-server + Hermes Agent (Nous Research) brain integration + CC0 starter faces + fan-art tribute faces. Hobby project, one maintainer, self-declared "beta, verified by scan and checksum, not yet tested on anyone else's hardware".
- License: MIT for repo code (LICENSE); tribute faces NOT MIT (personal non-commercial, removable on request); models listed with licenses (Phonon 40M is CC-BY-NC, gated). `THIRD_PARTY_NOTICES.md`, `licenses/`.
- Last commit 2026-11-14 (merge PR #17 "publish/dj7-source"); clone has 1 commit (squashed). Stars not in files [unverified].
- Size 91 MB: `firmware-src/` is 65 MB, of which `components/espressif__esp-dl` is 46 MB (vendored esp-dl with prebuilt `libfbs_model.a` for esp32, c2, c3, c5, c6, s2, s31, p4, 4-7 MB each; only s3 is needed), `main/` 15 MB (48 board dirs from xiaozhi, 629 .ogg locale sounds), `docs/` 1.4 MB. Then `faces/` 6.5 MB (PNG sheets + GIFs), `server/` 1.3 MB. Lesson: they vendored a whole upstream firmware tree; we should not.
- Languages: C/C++ firmware (cc 297, h 435, hpp 269), Python server add-ons, shell installers, Markdown (214 files), JSON.

## 2. Architecture
- Three tiers: (1) robot firmware (ESP-IDF 6.1.0, same as ours; `docs/TOOLCHAIN-VERSIONS.md`) derived from 78/xiaozhi-esp32 + fairy-stackchan, using mooncake + smooth_ui_toolkit; (2) voice server = patched upstream xinnan-tech/xiaozhi-esp32-server in Docker (pinned to upstream commit 4745186c, `server/addons/patched-server/UPSTREAM.md`, plus `patches/show-diff.sh` to diff against upstream); (3) optional Hermes Agent profile (API on localhost:8650) that talks to the robot via a stdio "stackchan MCP server" (15 tools) -> "hg bridge" HTTP (`POST /hg/api/device_call`, bearer token, allow-listed robot tools) -> robot-side MCP tools (`self.face.show`, `self.led.light`, `self.servo.set_angles`, `self.dance.preset`, `self.camera.take_photo`, `self.dj.mode`...).
- Protocol: xiaozhi WebSocket (Opus + JSON) and robot-side MCP tool calls (`firmware-src/.../main/mcp_server.cc`, `docs/mcp-protocol.md`). Public firmware ships with NO server address; the user types one in Settings > Server on first boot.
- Privacy posture: local by default. STT Parakeet MLX (Mac), TTS Phonon (local OpenAI-style server), Silero VAD, brain either Hermes + any model (cloud or Ollama) or Ollama-only; vision via Ollama gemma4:e4b. Cloud optional (xiaozhi cloud URL given as an option; AgentMail email is cloud). Only macOS Apple Silicon tested.
- "Add-on" packaging: `server/install-addon.sh <name> apply|dry-run|rollback` for 15 add-ons (actor-mode, agentmail, dj-mode, email-meme, fun-pack, hermes-profile, local-memes, local-stt-mlx, meme-previews, multilingual, patched-server, radio, rave-mode, smart-turn, stackchan-tools), each with README, `addon.conf`, config snippet, install/check/undo.

## 3. Wake word
- On device, offline, ESP-SR. Two detectors: WakeNet9 `wn9_jarvis_tts` ("Hey Jarvis", `sdkconfig.defaults.cores3-k151`) and MultiNet7 quantized (`CONFIG_SR_MN_EN_MULTINET7_QUANT`) for custom phrases "hey noose girl" / "hey news girl" and optional "hey yub" (`firmware-src/wake_words/custom_wake_word.cc`, `nous-girl-wake-words.patch`, `docs/WAKE-WORDS.md`). Spelling trick: write phrases phonetically in real English words (G2P guesses made-up names wrong).
- Both run together; MultiNet fed from AFE output, falls back to Jarvis-only if MultiNet cannot start. Sensitivity Low/Normal/High (MultiNet thresholds 0.30/0.20/0.12; WakeNet 0.72/default/0.55) stored in NVS `hg/ww_sens`; per-word switches `ww_on, ww_nous, ww_jarvis, ww_yub`; changes need "Restart to apply".
- Cost honestly documented: "Hey Nous-Girl" (MultiNet) keeps one CPU core busy while idle and can make audio choppy; v3.3 made it run only while idle. Barge-in by wake word was built (v3.6.5 `hg_barge.h`) then DISABLED (`kBuildAllowsBarge=false`) because with no echo cancellation her own voice masks the phrase. Tap-to-stop is the interrupt. AFE uses `FD_LOW_COST` AEC with `AEC_NLP_LEVEL_VERYAGGR`; one shared FD AFE instance for WakeNet and uplink.

## 4. Speech stack
- STT: Parakeet-TDT 0.6b v3 (MLX) primary, Whisper large-v3-turbo backup, local. TTS: Phonon 40M multilingual (en/es/fr/de/pt) with one server per language and a per-sentence language guesser that falls back to English 40M then 31M (`server/addons/multilingual`). LLM: Hermes or Ollama or any model. VAD: Silero on server.
- Smart end-of-turn (`server/addons/smart-turn`): Pipecat smart-turn v3.2 ONNX (8.7 MB, BSD-2) scores the last 8 s after 0.3 s of Silero silence (about 0.1 s CPU), answers about 0.5 s after the user stops instead of about 0.85 s; asks again every 0.3 s while unfinished, forces answer after 2.5 s; falls back to plain Silero on error; no audio saved; model fetched with SHA-256 check; mel features in numpy matching WhisperFeatureExtractor within 1e-7; has tests.
- Streaming Opus both ways via xiaozhi protocol; lip sync from audio meter (`hg_audio_meter.h`, `hg_lipmap.h`, `hg_vowel.h` + a small vowel model `hg_vowel_model.inc`) driving vowel mouth shapes (closed, half, open, wide_e, round_o, small_u, wide_i, smile).
- Barge-in: none by voice (see above); tap to stop.
- Persona: `SOUL.md` Markdown personality loaded by Hermes (`examples/nous-girl/SOUL.md`), with theory-of-mind-inspired uncertainty and repair rules. Memory: Hermes long-term memory (the only way to get memory; setups A/B/C table). Honest caveat in README: "SOUL.md guides responses. It does not enforce safety rules."

## 5. Features (docs/FEATURES.md has a quick map table: runs on / needs server / public now)
- Faces: 3 CC0 sprite styles (robot, boy, girl) x about 12 emotes (neutral, happy, sad, thinking, sleeping, pet, shake, speaking, listening, look_left, look_right, email, plus scowl) with per-frame ms timing and a lip-sync sheet; power key toggles drawn vs classic line face; custom art guide `docs/SPRITES.md`, `docs/EMOTES.md`, generator `faces/starter/make_starter_faces.py`.
- Touch: tap to talk or stop, hold 1.5 s for Settings, swipes for next/prev song, 3-pad head sensor (tap, hold, swipe), shake detection -> dizzy face. Servos: head look with limits (yaw -90..90, pitch 3..85), idle look-around, follow faces (esp-dl on device), dances (presets, recorded with remote, up to 60 s on SD). LED: 12 RGB, moods, talking lights, beat sync. Camera: "what do you see" (photo -> server vision model, max 1 per 5 s), face ID for enrolled people.
- Music from SD or server, DJ mode with set lists (`dj-setlist/1` JSON with timed cues), 13-band EQ on screen, rave mode (soft colours, max 3 pulses/s, no red strobe, voice-only, grown-ups), internet radio (8 s timeout then moves on), Actor Mode scripts (`validate_scene.py`), fun pack (trivia, spelling bee, memory games, story time), local meme maker (Pillow, ~60 templates, word filter), 160x120 meme previews in PSRAM, AgentMail email with read-back and allow-list, crash report page, multi-network Wi-Fi + phone hotspot, on-robot Settings app with 14 tiles. No timers or alarms found [unverified]. Kid mode: no switch, by design (see 6).

## 6. Security and kid safety
Good:
- `SECURITY.md`: private vulnerability reporting, scope list (secrets in repo, firmware connecting somewhere the user did not set, network control of camera/mic, docs that leave servers open). Public firmware has no embedded server address and "connects nowhere" until set.
- `.github/scripts/safety_scan.py` run by `checks.yml` on every PR: secret regexes (private key, GitHub, OpenAI-style, Slack, AWS, Google), emails, private domains from a repo secret, non-documented LAN IPs, files over 2 MB, broken relative links; allow-list JSON by path+line+category; PR template checklist includes "Kid-safe: nothing a parent would not want on a child's robot". Dependabot for Actions. `persist-credentials: false`, `permissions: contents: read`.
- hg bridge: bearer token, localhost/private LAN only, allow-listed robot tools only; MCP wrapper caps head angles and LED brightness; patched server adds optional OTA key and device-ID allow-list; admin page localhost only.
- Code-level guards independent of the model: meme maker refuses swearing, violence, drugs, politicians, named family members; email only to an allow-list file outside the repo (private perms), read-back, `confirm=true` matching a read-back in last 5 min, single use, 10/hour, log, key read from `.env` at send time and never logged; photo rate limit; meme preview limit 160x120 / 64 KB server side and 256 KB + Content-Length required on device; rave colour caps for photosensitivity.
- Self-hosting docs warn: protect public addresses (Cloudflare Access service token or device-ID allow-list), keep keys in `.env`, hotspot guide.
- Roadmap item "Classifier for learning": approve / reject / log for what she learns, "anything unclear waits for a grown-up".
Weak:
- Transport is xiaozhi `ws://` on LAN without TLS; device identity is the device-ID header (upstream design); OTA lock-down is optional and off by default [unverified default].
- Kid safety is mostly SOUL.md prompt (self-admitted not enforced); radio has "no kid filter"; camera face ID stores enrolled people [unverified where]; no retention/clear UI described for Hermes memory ("Memory with Hermes Agent: documenting... coming soon").
- Beta/untested on others' hardware; vendored 46 MB third-party tree complicates dependency audit; fan-art tribute assets have unclear rights (they flag it); Phonon voice is non-commercial.
- Safety scan covers regex only; 2 MB file limit contradicts the 65 MB firmware tree (firmware-src is presumably allow-listed or committed differently [unverified]).

## 7. Performance and memory
- LVGL memory pool in PSRAM (`lvgl_psram_pool.h`, `LV_MEM_POOL_ALLOC`), alt no-PSRAM pool header. Wake-word upload cache: single 64 KB PSRAM ring (last 2 s) shared by WakeNet and MultiNet, replacing per-chunk internal-SRAM allocations (`main/audio/README.md`). Single AFE instance. Meme previews downloaded to PSRAM, 160x120 drawn at 2x for a quarter of memory; reject without Content-Length or over 256 KB (fixed dj6 reboot on previews, so dj6 is flagged "avoid" in VERSIONS.md).
- Idle power: dim after 300 s on battery, not on USB; MultiNet only while idle. Free PSRAM shown on About page; crash report with reset reason + heap + battery sent to server as `hg_boot`.
- Release hygiene: three flash artifacts per face (full 0x0, app 0x20000 keeps Wi-Fi, assets 0xB00000 faces + wake models) with SHA256SUMS; known-bad versions called out; rollback one step at a time.

## 8. UI / screens
- Viewed: `faces/starter/starter-faces-combined.png` (3 rows x 10 emotes), `faces/starter/robot/preview.png` (full animation sheet with per-frame ms timings and lip-sync set). Also exist: boy and girl previews, 12 GIFs per face under `faces/starter/*/gifs/`, `faces/tribute/nous-girl/preview.png`. No photos of the actual robot or the Settings screen in the repo (Settings documented only by text tables).
- Visual design: monochrome anime line art on white, bold outlines, tiny gray shading, emote conveyed by overlays (sparkles, hearts, sweat drop and "?" for thinking, ZZZ for sleeping, spirals + motion lines for shake dizzy, sound arcs for listening, envelope flying across for email, tears for sad). Robot character has cat-ear antennae and a monitor face; consistent grid, each state a short 3-12 frame loop with deliberate durations (neutral 2400 ms hold + 120 ms blink, shake 90 ms frames). Reads at 320x240 and is easy to recognise at a glance. Weakness: grayscale only and generic, not a distinct brand; no screenshots of real hardware.
- Rating 4/5 for the face system (esp. the emote vocabulary, preview sheets with timings, per-face GIFs and the generator script); 2/5 for UI documentation visuals. What we could copy: the emote vocabulary and state-to-emote mapping table (`docs/EMOTES.md`), preview sheet generator with frame-ms labels, overlay-icon language for states, `pet`/`shake`/`email` states, plus a sprite-sheet spec for community faces.

## 9. README and docs
- README is an excellent model of honest promotion: status banner ("hobby, one maintainer, heavy AI assistance, untested by others"), current/safe/avoid version callout, "Where to get help" table (Q&A, Issues, Ideas, Show and tell, private security, social), "Pick a brain" comparison table (memory / tools / robot tools / fully local / difficulty), feature bullets linking to per-feature docs, "What runs where" table, first-boot four steps, models table with sizes and licenses and "no model files in repo", "Coming soon (not released yet)" separated from shipped, and a dedicated "AI transparency" section ("built with a lot of help from AI coding agents... a human reviews, flashes and tests everything on the real robot before it is called working").
- `docs/FEATURES.md`: uniform five-part template per feature (what it does / turn it on / use it / set it up yourself / turn it off), "Runs on / needs your server / public now" quick map. `docs/SETTINGS.md`: every setting with default and when to use it. `VERSIONS.md`: changelog with SHA-256, known issues, flash and rollback commands. PLATFORMS, HOTSPOT, SELF-HOSTING, RELEASING docs. Issue templates (bug, feature, question), PR template with privacy and kid-safe checklist, CODEOWNERS, CODE_OF_CONDUCT, CONTRIBUTING (redact logs first). No badges, no demo video/GIF of the real robot in README. Tests: `server/addons/{smart-turn,email-meme}/tests`, `firmware-src/.../scripts/tests`; CI is only the safety scan + docs link check, no firmware build CI.

## 10. Top ideas to adopt
1. Smart end-of-turn model (Pipecat smart-turn v3.2 ONNX, 8 MB, BSD-2) on our Python host after short Silero silence; fall back on error; log only scores. Cuts about 0.35 s and stops cut-offs mid-thought.
2. Wake-word design: WakeNet for a reliable built-in word plus MultiNet7 for a custom phrase with phonetic spelling, sensitivity Low/Normal/High exposed in Settings, per-word switches, fall back when MultiNet cannot start; run MultiNet only while idle; document the CPU cost.
3. Safety scan CI (`safety_scan.py`): secrets, emails, private domains (from a secret), LAN IPs, file size, broken links, with a path+line+category allow-list; plus a PR checklist line "kid-safe".
4. Code-enforced guardrails behind tools, not prompt-only: confirm token tied to a read-back within 5 min and single use, hourly rate limit, recipient allow-list outside repo, angle and brightness clamps, size caps on images (check Content-Length before download).
5. Emote vocabulary and sprite spec: 12 named states with overlay icons, per-frame ms timing, vowel-shaped lip-sync set, preview sheet generator, community face guide; ship starter faces as CC0.
6. Honest README structure: status banner, current/safe/avoid versions, "Pick a brain" capability table, "What runs where", models table with licenses, "Coming soon" fenced off, explicit AI transparency paragraph, "Where to get help" table.
7. Release artefacts split by flash region (full / app keeps Wi-Fi / assets) with SHA256SUMS, known-bad version flags, one-step rollback commands; crash report page (reset reason, heap, battery, PSRAM) also sent to server.
8. Add-on installer pattern with `dry-run | apply | rollback`, backups to a timestamped folder, config snippets, and per-add-on check commands; plus an Actor Mode / set-list JSON (`dj-setlist/1`, timed cues) idea for scripted shows.

Avoid: (1) vendoring a whole upstream tree (46 MB esp-dl with every chip's prebuilt lib, 48 boards) into the repo; use pins and component manager lock files. (2) Prompt-only kid safety ("no kid switch on the robot") and unfiltered radio next to a kid persona; keep age gates in code. (3) Shipping a disabled-in-build feature behind a dead NVS key (`ww_barge` ignored) and "beta, untested by others" binaries without firmware CI.

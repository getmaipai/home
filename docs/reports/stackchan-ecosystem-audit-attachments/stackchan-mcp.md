# Audit: migratorywhale/stackchan-mcp (local clone, read-only)

## 1. What it is
- Python MCP server (stdio + Streamable HTTP) plus its own PlatformIO/Arduino CoreS3 firmware, host voice bridge, face tracker, phone voice-upload receiver and an opt-in outbound WSS relay. "Give your AI companion eyes, ears, voice, skin." Authors: Isa + xiaoke (an AI persona) with Codex hardening. Single squashed commit 2026-10-07 (release/stackchan-20261007), MIT, ~180 files, 4.2 MB (firmware/src/gif_assets.h alone 923 KB, uv.lock 338 KB). Languages: Python (mcp_server ~160 KB, scripts ~100 KB, tests ~220 KB), C++ firmware, shell. Stars [unverified]. NOT the same project as kisaragi-mochi/stackchan-mcp (the gateway that stackchan-cloud-mcp patches; that one has say/listen/set_avatar tools).

## 2. Architecture / protocol
- MCP client <-> `python -m mcp_server.server` (FastMCP; stdio default, `--http` Streamable HTTP on 127.0.0.1:8002) <-> device HTTP API on LAN port 80 (docs/http-api.md is the shared contract) or relay transport.
- Tools (mcp_server/mcp_tools.py): `stackchan_say(text, lang="zh")`, `stackchan_listen(lang)`, `stackchan_see()` (returns JPEG as MCP Image and also shows the same frame on the robot screen for 6 s = visible "I am looking" indicator), `stackchan_face(expression)` (calm thinking happy sleepy shy smug pouty), `stackchan_move(x -128..128, y 0..90, speed 0..100)` (clamped), `nod`, `shake`, `home`, `stackchan_sense` (SHT31/QMP6988), `stackchan_status`, `stackchan_health` (config+deps+device), `stackchan_config_summary` (no secrets), `stackchan_playback_status` (queues, mic state, gesture, heap, PSRAM), `stackchan_booth_mode(enabled|null)` (privacy: blocks ALL mic capture, persisted in NVS), `stackchan_voice_inbox(limit)`, `stackchan_voice_inbox_clear`.
- Device HTTP: POST /play (WAV URL), POST /play/pcm (24 kHz mono s16le, seq/final/session, 128 KiB body), TCP PCM stream :9090 with one ASCII header line (`STACKCHAN_PCM_STREAM/1 session= rate= channels= width=`; reply OK/ERR; 120 ms prebuffer, 10 ms I2S DMA frames), UDP PCM session (`SCP1` magic + token + seq + timestamp, 10 ms frames), GET /audio/status, GET /audio (consuming read), POST /move /home /nod /shake, POST/GET /face, GET /snapshot, /env, /servo/status, /touch/status, /playback/status, GET/POST /booth.
- Outbound relay (docs/outbound-channel.md, mcp_server/outbound_relay.py, firmware outbound_service.cpp): device dials out to wss://host/stackchan/ws (CA-verified TLS, no insecure fallback, NTP required), device bearer token separate from controller token, hello within 5 s, heartbeat 10 s, close after 35 s silence, 8 KiB JSON limit, 128 KiB PCM/JPEG, command envelope `{"v":1,"id":<32hex>,"expires_at_ms",method,path,query,body}` with mandatory expiry checked against device clock, binary frames `SCB1|id|bytes`, single in-flight slot (409 on concurrency, never queued), 20 s deadline (504 + channel close), no automatic replay of any command, offline 503. Local MCP uses loopback relay URL + token file.
- Firmware targets: Arduino/PlatformIO ESP32-S3 CoreS3 + Stack-chan servos (SCServo SCSCL drivers), Si12T 3-zone touch, GC0308 camera, AnimatedGIF 192x192 faces (7 expressions), WiFi portal. Cloud: optional, user-hosted relay only; TTS/ASR via Fish Audio / ElevenLabs / edge-tts are third-party cloud.

## 3. Wake word / speech
- Host-side, not on device: scripts/stackchan_voice_bridge.py polls the robot mic (GET /audio), Groq-Whisper-via-Fish ASR, wake word list `STACKCHAN_VOICE_WAKE_WORDS` matched at transcript start after stripping filler words (好的/嗯/啊...) with duplicated-first-char tolerance (scripts/stackchan_frontend_wake.py `match_wake_word`). Transcripts are forwarded to a frontend `/wake` URL with a provenance prefix `[Stack-chan语音输入] ` (touch: `... （触摸）`). Touch tap forces a recording and bypasses wake-word matching; pet gesture (fwd+back swipe within 1500 ms) = happy face 5 s, no network. Phone browser upload page + rate-limited upload receiver as an alternate mic. Quiet-minutes option and retry on 409 busy.

## 4. Features / wording
- Behaviors: host face tracking only after an explicit trigger (wake/touch/say), smoothing + dead zone + step limits + slow servo, single face, no biometrics, returns home after ~2 s loss and never sweeps; camera/touch GPIO 11/12 sharing handled (touch suspended during camera; firmware self-restores after 5 s if host dies). Audio engineering: de-click, gain/limiter, UDP pacing factor, ElevenLabs whole-utterance buffering with Fish fallback and no silent Edge fallback, no second paid TTS call on playback failure. Timing breakdown returned in tool result strings and OpenTelemetry-style events (`emit_event`, request ids).
- Tool wording: most tools have NO docstring (names only; weak for agents). Good examples: `stackchan_booth_mode` docstring spells out persistence, what it does not block (speaker, camera), "never toggles implicitly or retries", "check success and every status field; failed/partial/unknown does not confirm privacy", "after an uncertain write, query first". `stackchan_sense` docstring suggests when to use it (barometric drop, headaches). Results are short emoji-prefixed strings; errors state availability is "unconfirmed" rather than claiming offline. Invalid expression returns the list of valid choices.

## 5. Security
- Good: HTTP transport fails closed without STACKCHAN_MCP_AUTH_TOKEN (server.py `ensure_http_auth_configured`), Bearer middleware with `hmac.compare_digest`, loopback bind default, public tunnel opt-in (`STACKCHAN_ENABLE_PUBLIC_MCP_TUNNEL=1`), docs steer to Tailscale (tailscale serve on loopback) with an explicit argument why hostname secrecy is not a security model (CT logs); upload receiver requires token for non-loopback, header-only token (query token rejected), per-minute rate limiter (default 12), origin allowlist CORS, token regex redaction in logs; relay: separate device/controller tokens (>=24 chars, from files), tokens never in URLs, no redirects followed on relay requests, expiry-stamped commands, no replay, single slot, single-device not a general proxy, no insecure TLS fallback; privacy mode persisted in NVS with verified-state reporting and priority admission; `audit_tool_call` logs every tool call (text length only, not text); repo security audit script (forbids tracked .env/config.h, real IPs, trycloudflare URLs, unpinned actions/deps), CodeQL, Dependabot with cooldown, exact pins, SHA-pinned GitHub Actions, SBOM on release.
- Weaknesses: device LAN HTTP API has no authentication at all (firmware/src/http_server.cpp has no auth code; SECURITY.md says trusted LAN only) - anyone on the LAN can read /snapshot, consume /audio, move, speak, toggle booth mode; generated-WAV server on LAN is unauthenticated (documented); `stackchan_see` writes every photo to disk (`cam_<ms>.jpg` in AUDIO_DIR, mcp_tools.py) with no retention policy; no per-tool rate limit or confirmation for camera/say on the MCP side; single shared bearer token (no scopes); `stackchan_config_summary`/health reveal LAN IPs to the model; voice transcripts become agent prompts (prefix is provenance only, no injection filtering, no speaker identity or age/surface gating) and anything audible near the robot can drive the agent; stackchan_say text passes to cloud TTS (privacy); AGENTS.md tells agents "do not read CLAUDE.md" (instruction aimed at a different assistant, noted as policy hygiene).

## 6. Performance / reliability
- Transport fallback ladder TCP PCM -> staged PCM -> WAV with `started` flag (never fall back after audio began), ElevenLabs buffer cap 2 MiB (~43 s), PCM sequence ordering, single active PCM session, WAV download watchdog and recovery, device `playback/status` health snapshot (queue depths, download_age_ms, mic_running authoritative), per-request timeouts (status/command/audio/probe separately configurable, probe clamped 1..30 s), curl-subprocess HTTP transport for macOS Local Network privacy, launchd plist examples, duplicate-consumer protection for the single-consumer /audio read, consuming-read hazards documented, no automatic retries on non-idempotent writes, 20+ dated troubleshooting write-ups (audio noise, stutter, consecutive audio, no-audio, remote-WAV publish race, touch/camera I2C, servo). Voice-bridge retries on 409 busy.

## 9. Top 8 ideas to adopt
1. Ship an MCP server for our host (FastMCP stdio first, loopback Streamable HTTP second) wrapping our WebSocket JSON tools; fail closed on missing token, `hmac.compare_digest`, loopback default.
2. Tool vocabulary: short namespaced verbs (`robot_say/see/face/move/nod/shake/home/sense/status/health/playback_status`) plus a no-secrets `config_summary`; return concise strings with explicit "unconfirmed" wording, and list valid enum values in the error.
3. Privacy mode tool modeled on `booth_mode`: explicit set (never toggle), persisted on device, returns verified state fields, docstring tells the agent how to interpret partial results and to query before retry; maps well to our age/surface gates.
4. `see` shows the captured frame on the robot display for several seconds (visible camera indicator) and never persists by default.
5. Relay design if we ever go off-LAN: device dials out over CA-verified TLS, separate device/controller tokens, expiring command envelope, single in-flight slot, no replay, heartbeat 10 s/35 s timeout.
6. Audio transport ladder with a `started` flag (never replay after audio started), PCM prebuffer 120 ms, `playback_status` health snapshot with queue depths and watchdog ages.
7. Voice-input provenance prefix on transcripts handed to an agent (and a distinct one for touch), wake-word match after filler stripping, tap-to-talk bypass; use it as the hook where we apply our injection/age gates.
8. Repo-level security audit script plus SHA-pinned actions, exact dependency pins with cooldown, dated troubleshooting notes, PR template with "hardware impact" and "safety notes" boxes, firmware native tests for protocol/gesture logic.

## 9b. Avoid
1. Unauthenticated device HTTP API relying on "trusted LAN" (add a per-device token on our WebSocket and on any HTTP).
2. Tools with no descriptions (agents guess); also emoji-heavy result strings that waste tokens and break parsers.
3. Writing every camera frame to disk and a single unscoped shared bearer token; consuming-read endpoints (`GET /audio` clears state) that make safe probing hazardous.
